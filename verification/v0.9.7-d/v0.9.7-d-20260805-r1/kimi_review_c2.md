## 5. Remaining contradictions / documented limitations

- **RC2-01 - Primary CTA renders ink-on-red (gate).** Measured glyph color `#1a1c2c` on fill `#e00047` in the "Open Revision" / "前往修改" buttons (en/zh, desktop+mobile bottom captures; desktop CTA at y=725-768). Contrast ~3.4:1 - legible, but below the documented "white text (4.93:1)" (§3) and the §14 "all text pairs >= 4.5:1" baseline for 1rem/700 button text (16px bold is not WCAG-large). Root cause: `[data-testid="stBaseButton-primary"] { color: var(--px-action-text) !important; }` (`pixel_art.py:433-441`) sets color on the button element, but Streamlit wraps the label in a child `<p>`/`<span>` matched by the global typography rule `.stApp p/span/div { color: var(--px-text); }` (L364-369); a direct child rule beats inherited `!important`. One-line shared-layer fix (extend the primary selector to the label child); structural in the shared layer, first evidenced now that below-fold captures exist.
- **RC2-02 - `.px-field-error` keeps the tint token as text color (gate).** `pixel_art.py:1160` `color: var(--px-status-error)` = `#fdeaef`; with the new `div.` type selector the declaration now ties `.stApp div` at (0,1,1) and wins through injection order (L1256), so field errors render ~1.1:1 instead of the contracted `#a30d3d` (6.78:1, §3 error row). Not visible on Journey (no field errors) but it is the only error-text voice Writing/Feedback will inherit. One-line token swap to `--px-status-on-error`; extend the matrix's color assertion to a rendered field error.
- **RC2-03 - Dashed-border recipes silently render borderless (gate).** `div.px-notice-dashed` (`pixel_art.py:969`) and the empty-state rule (`pixel_art.py:976`) both use `border: var(--px-border-thin) dashed`; since `--px-border-thin` is already a full `2px solid #1a1c2c` shorthand (L279), the declaration is invalid at computed-value time and drops to unset - the winning rule, so the base `.px-notice` border does not rescue it. Measured: the legacy practice notice ("This practice activity has no priority reference.", `neutral_box(..., dashed=True)`, `journey.py:261`) renders tint-only with zero border pixels (en bottom, y=240-290). Same defect class as KB-01/RC-03, surviving in two rules; §3's "evaluation unavailable" and "legacy/unlinked" recipes lose their documented border channel. State still carries tint+icon+text, so this is contract fidelity, not an accessibility failure. One-line fix per rule.
- **RC2-04 - §9 notice spec vs implementation (RC-07 persists).** Spec: 20px icon + bold localized label + body. Implementation: 18px icon, no label element (`components.py:250,275`; measured glyph box 18px). Under the wording-frozen constraint the label clause is unsatisfiable for fixed-copy notices; amend §9 to 18px and state that the label channel lives on the badge.
- **RC2-05 - Next-step panel taxonomy (RC-08 residue).** The "Suggested next step" block renders 4px ink border + shadow-sm (measured desktop: border y=610-613, shadow 2px; mobile: 2px+2px per the §5 scaling). §7 declares the focused-panel recipe uninstantiated on Journey, leaving this 4px border outside §5's three sanctioned 4px uses. Either designate the block as the focused panel (and align the shadow token) or document `.px-student-action` as its own recipe.
- **RC2-06 - `.px-divider` remains dead CSS, undocumented (RC-10 persists).** `pixel_art.py:848-852` still specs a 4px-ink rule that Streamlit's native hr styling overrides; measured sidebar/main hairlines remain 1px (pre-existing). Repair the rule or document the native hairline as the separator pattern (§9 currently documents only the section-header hairline).
- **RC2-07 - Page-header rule undocumented (RC-03 doc residue).** The now-valid `.px-page-heading` 4px structural rule has no visible consumer on Journey (measured: no rule under the title in any capture) and §9's page-header spec never mentions it; code and doc must agree on whether the rule exists.
