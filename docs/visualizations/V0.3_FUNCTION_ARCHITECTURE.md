## 纵向证据决策流

```mermaid
flowchart TB
    NEW["新作文已完成单篇分析与诊断"]
    LOAD["读取同一 student_id 的历史作文、指标与结构化诊断"]
    JUDGE["逐篇与当前作文比较<br/>任务、体裁、写作条件、长度、时间、分析版本"]
    STATUS{"可比性状态"}
    INCLUDE["comparable<br/>纳入主要分析"]
    SENS["partially_comparable<br/>默认排除；可选敏感性查看"]
    EXCLUDE["not_comparable<br/>排除并保存原因"]
    COUNT{"主要分析记录 ≥ 3?"}
    INSUFF["数据不足<br/>不判断趋势"]
    CALC["计算个人基线、8 个指标趋势、变异性与问题轨迹"]
    SNAP["保存不可变 LearnerProfileSnapshot<br/>包含规则、分析与配置版本"]
    FILTER["仅选择允许给 LLM 的结论<br/>转换为历史证据 ID"]
    LLM["DeepSeek 或 LocalDemo<br/>只能引用允许的 H-ID"]
    VERIFY["Pydantic + 引用范围验证<br/>合格后保存反馈与调用记录"]

    NEW --> LOAD --> JUDGE --> STATUS
    STATUS --> INCLUDE --> COUNT
    STATUS --> SENS
    STATUS --> EXCLUDE
    COUNT -->|"否"| INSUFF --> SNAP
    COUNT -->|"是"| CALC --> SNAP
    SNAP --> FILTER --> LLM --> VERIFY
```

## 一次提交的关键顺序

```mermaid
sequenceDiagram
    participant U as Streamlit
    participant A as FastAPI
    participant S as SubmissionService
    participant L as Longitudinal services
    participant R as Repository
    participant P as Prompt + Provider
    participant V as Validator

    U->>A: POST /api/v1/submissions
    A->>S: 已验证 EssaySubmission
    S->>R: 保存原始作文、指标、诊断
    S->>L: 基于当前作文重建 Snapshot
    L->>R: 读取历史并保存新 Snapshot
    L-->>S: 筛选后的趋势、问题与优先项
    S->>P: 当前作文证据 + 允许的 H-ID
    P->>V: 候选结构化反馈
    V-->>P: Schema、诊断 ID、历史 ID 与练习关联校验
    P-->>S: DeepSeek 成功结果或已验证的 LocalDemo 回退
    S->>R: 保存反馈、练习与 LLM 调用审计
    S-->>A: SubmissionResponse
    A-->>U: HTTP JSON
```

## 备份核对点与研究边界

- 主要趋势只纳入 `comparable` 记录；`partially_comparable` 默认不影响结论，并保留排除原因。
- 少于 3 条主要记录时返回“数据不足”，不把变化解释为能力提升或下降。
- 趋势置信度最高为 `medium`；规则、阈值和版本号均可追溯，但尚未经教育实验验证。
- 问题轨迹只读取结构化诊断；“最近减少”要求至少 4 条可比记录、此前至少出现 2 次且最近 2 次未出现。
- LLM 不接收被排除作文或原始历史序列，不重新计算趋势，不得加强本地置信度。
- DeepSeek 失败时使用同一 Schema 和证据校验器验证 LocalDemo 回退；真实调用审计不保存 API Key。
- PostgreSQL、教师仪表板、CEFR、自动评分、能力增长判断和微信小程序均未在 v0.3 实现。

纯文本回退：`Streamlit → FastAPI → SubmissionService → 单篇分析 + 纵向服务 → Repository/SQLite → 筛选后的 Snapshot 证据 → PromptBuilder → DeepSeek/LocalDemo → FeedbackValidator → 保存结果`。
