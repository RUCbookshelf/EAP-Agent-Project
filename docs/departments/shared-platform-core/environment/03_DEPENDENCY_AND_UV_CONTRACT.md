```text

        |
        v
uv.lock               (AUTHORITATIVE lockfile: fully pinned, hash-verified, 87 packages)
```

complete transitive graph (wheels, sdists, hashes, upload times) is recorded in `uv.lock`.

## 3. Requirements the contract satisfies

- **Deterministic resolution:** exact pins + full lockfile; `uv lock` reproduces the same graph
  (verified: `Resolved 87 packages`, `uv.lock` revision 3, `requires-python ">=3.11, <3.13"`).
- **Lockfile reproducible:** `uv lock --check` passes (no drift after a clean lock generation).
- **Drift detectable:** `uv sync --check` reports `Would make no changes` on a correct
  environment; the environment verifier (WU6) and drift guards (WU12) surface `LOCKFILE_DRIFT`.
- **Production vs development explicit:** runtime dependencies in `[project].dependencies`;
  test/browser tooling in `[dependency-groups].dev` (pytest 9.1.1, playwright 1.61.0); NLP model
  in `[dependency-groups].nlp`. `[tool.uv].default-groups = ["dev", "nlp"]` makes a plain
  `uv sync` produce the complete development environment.
- **No cross-department mutation:** per-worktree `.venv` is gitignored and owned by the worktree;
  no department can install packages permanently into another department's environment.

## 4. uv ownership and version policy

- **Owner of repository-wide Python dependency changes: Shared Platform & Core.**
  Other departments may *request* dependency changes (with evidence and verification), but must
  not silently mutate `pyproject.toml`/`uv.lock` or install packages into the shared contract.
- Dependency update flow (owned by Shared Platform & Core): change `pyproject.toml` →
  `uv lock` → `uv sync` → run the drift guards and affected suites → full non-live core →
  commit lockfile + manifest together, with the verification record.
- **uv version policy:** uv itself is a developer tool, not a product dependency. The bootstrap
  provisions a minimum supported uv (0.12.x at the time of this contract) and records the actual
  version in verification output. Lockfile format is `version = 1`; `uv lock --check` enforces
  lock/uv compatibility on every verify run.
- uv stores managed Python runtimes in `UV_PYTHON_INSTALL_DIR` (user-level; default
  `%APPDATA%\uv\python`, which is machine-healthy on this machine) and package downloads in the
  user-level uv cache. The bootstrap probes the default locations and falls back to healthy
  user-level alternatives when a default is unusable in the current context (on this machine the
  restricted agent context provisions into `C:\Users\16073\.uv-python` instead). Both stores are
  shared, written only by uv itself (self-locked), and never written by agents directly
  (see 07_PARALLEL_WORKTREE_SAFETY.md).
