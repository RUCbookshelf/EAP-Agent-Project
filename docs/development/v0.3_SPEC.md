# v0.3 specification — longitudinal analysis engine

## Goal

Build a cautious, traceable engine for submission comparability, personal baselines, metric time series, issue trajectories, variability, trend confidence, versioned learner snapshots, and longitudinal APIs.

## Preconditions

v0.2 is completed, accepted, visualized, committed, and its tests remain green.

## In scope

- Versioned configuration and domain models for comparability, baselines, trends, issue trajectories, priorities, and snapshots.
- Comparability service with necessary, important, and limiting conditions and explicit reasons.
- Baseline and progress services using only eligible comparable submissions.
- Transparent direction, variability, and conservative confidence heuristics.
- Persistent, append-only learner profile snapshots and Repository/API access.
- Structured progress evidence supplied to LLM feedback without letting the LLM recalculate trends.
- Four repeatable synthetic learner scenarios, all 55 required test groups, docs, acceptance report, visualization, human review guide, and Git commit.

## Out of scope

- CEFR, overall ability scores, validated growth claims, ranking, class comparison, black-box composite scores, dashboards, v0.4 features, WeChat, or cloud deployment.

## Architecture changes

Add longitudinal domain/config modules and `ComparabilityService`, `BaselineService`, `ProgressService`, and `LearnerProfileService`; extend Repository protocols and SQLite implementation for append-only snapshots.

## API changes

Upgrade `/api/v1/students/{student_id}/progress` and `/profile` with filters and truthful structured longitudinal output. Errors stay consistent and safe.

## Database changes

Add versioned migrations for learner profile snapshots and any supporting evidence fields without deleting or overwriting existing records.

## Dependency changes

Prefer the standard library and current dependencies; document any required addition and revalidate a clean installation.

## Test requirements

Cover all 55 groups in the governing objective, including v0.1.1/v0.2 regression, startup, persistence across restart, no-key operation, forbidden-label checks, and LLM evidence-ID validation.

## run.bat impact

Continue running migrations before starting both services; verify the latest migration and both endpoints.

## Documentation requirements

Update all named v0.3 documents; add longitudinal, comparability, learner profile, acceptance, visualization, and human-review materials.

## Acceptance criteria

All 27 v0.3 criteria in the governing objective must have direct evidence and an independent Git commit.

## Stop condition

After acceptance, visualization, roadmap update, commit, and human review guide, stop with v0.4 still `not_started`.
