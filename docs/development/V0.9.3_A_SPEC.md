# V0.9.3-A Specification: Runtime Reliability and Service Lifecycle

**Date:** 2026-07-31
**Status:** in_progress
**Target:** Fix REL-001 — eliminate intermittent FastAPI startup hang

## 1. Root Cause Confirmed

app/api/main.py line ~693: app = create_app() runs at module level.
create_app() synchronously:
1. load_settings() — fast
2. Database(path).initialize() — applies migrations
3. build_submission_service() which calls:
   - build_analyzer() → SpacyAnalyzer() → loads en_core_web_sm (~8s)
   - build_router() → DeepSeekProvider
   - LearnerProfileService, RevisionService, etc.
4. Registers all routes

If any of steps 2-3 block (spaCy model lock, DB contention), uvicorn accepts
TCP but the ASGI application never reaches the request handler. No HTTP
response is possible until ALL initialization completes.

## 2. Solution Architecture

### 2.1 New module: app/lifecycle.py

ServiceState enum: starting, ready, degraded, failed, stopping
ServiceLifecycle dataclass: state, timestamps, stages, health info
Thread-safe state transitions via threading.Lock

### 2.2 FastAPI lifespan

Replace module-level create_app() with:
- Minimal module-level app: just liveness endpoint
- lifespan context manager: runs heavy init on startup
- All existing routes still registered inside lifespan after init

### 2.3 Endpoints

GET /api/v1/system/live — liveness (process alive, can serve HTTP)
GET /api/v1/system/ready — readiness (all required deps available)
GET /api/v1/system/health — existing, enhanced with lifecycle state

### 2.4 Initialization order

1. Module import: FastAPI() with liveness route only
2. lifespan startup:
   a. state = starting, record timestamp
   b. load settings
   c. init database
   d. build analyzer (may take 8s; failure → degraded or failed)
   e. build services
   f. register remaining routes
   g. state = ready (or degraded)
3. lifespan shutdown: state = stopping

### 2.5 run_local.py changes

- Poll GET /live first (fast, confirms process alive)
- Then poll GET /ready with bounded retries (max 30)
- Display state: process alive → starting → ready → done
- On timeout: report last known state

### 2.6 Streamlit API client changes

- Reduce default timeout from 90s to 15s
- Add lifecycle state checking before showing generic error
- Distinguish: api not running vs api starting vs api failed

### 2.7 run.bat changes

- Add stale process cleanup (kill existing uvicorn/streamlit on startup)
- Use readiness polling instead of unbounded wait_http
- Display state transitions to user
