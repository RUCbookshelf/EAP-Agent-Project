# v0.7 human review guide

1. Start with `run.bat`, open Streamlit, and choose **Learner Model audit**.
2. Enter a pseudonymous student ID to view the latest Learner Profile Snapshot v2.
3. Expand **Task clusters** and confirm genre, timing, tool, revision mode, analyzer and metric-version separation.
4. In the representative section, compare source, representative and excluded IDs; verify final-or-latest on each Revision Group.
5. Inspect Data Sufficiency: 1 task insufficient, 2 limited, 3–4 provisional, 5+ adequate descriptive trend.
6. Inspect Metric Trajectories and verify each point against its submission, AnalysisRun, metric/analyzer version and confidence.
7. Inspect Diagnostic Trajectories and confirm selected, eligible, monitored and suppressed counts remain separate.
8. Confirm current learning targets are a subset of current verified selected priorities and never exceed two; zero is valid.
9. Inspect `HE######` History Evidence source IDs, Task Cluster, versions, status and limitation.
10. Use `GET /api/v1/students/{id}/learner-model/snapshots` or the historical-snapshot selector; older `LP######` and new `LPS######` snapshots must both parse.
11. Use **Preview without saving** to compare representative strategies; confirm snapshot history count does not change.
12. In Local administration, rollback the active `config-v0.7.0` to preserved parent `config-v0.6.2`; reactivate only after validation.
13. Run Case A–I in `tests/fixtures/learner_model_v07/cases_a_i.json`: insufficient, pairwise, repeated diagnosis, current suppression, Revision Group, genre split, tool split, version split, zero target.
14. For live DeepSeek review set `RUN_LIVE_LLM_TESTS=1` locally and run only `tests/test_live_deepseek_v07.py`; confirm three comparable tasks, provider deepseek, validation passed, no fallback, v0.7 prompt/schema and HE evidence.
15. Review current thresholds: pairwise 2, direction 3, adequate 5, max targets 2, emerging 2, recurring 3, persistent tasks 3, persistent selected 2, reduction window 2, prompt history maximum 5.
16. Treat every clustering, sufficiency, variability and trajectory threshold as unvalidated until literature review and human-coded calibration are complete.
17. Before v0.8, decide task-equivalence evidence, human adjudication workflow, minimum task counts by genre, cross-version bridging, strength validation and privacy/retention policy. Do not begin CALF automatically.

Student view must remain concise and free of raw parser nodes, numeric research rankings, suppression lists and complete profile JSON. Researcher view must retain lineage and exclusions.
