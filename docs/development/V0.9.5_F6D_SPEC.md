## Objective

Behavior-preserving Router dependency and persistence-boundary refactor:
remove every active Practice Router dependency on the broad `Database`
facade; replace it with three exact consumer-owned Ports
(`PracticeSubmissionReadPort`, `PracticeReadPort`, `PracticeWritePort`);
remove the dormant Repository dependency from `PracticeService` (source
confirms it is persistence-free); keep Router ownership of the
Attempt-first/Evaluation-best-effort orchestration; preserve every endpoint,
schema, status code, domain calculation, and error behavior; supply only the
existing facade-owned `SQLiteSubmissionRepository` and
`SQLitePracticeRepository` (plus the existing facade-owned Learner reader
required by the preserved `require_student` guard, see section 8).

## 9. Exact Attempt/Evaluation sequence (current HEAD, authoritative)

`POST /api/v1/exercises/{exercise_id}/attempts`:

1. `practice_reader.get_exercise_instance(exercise_id)`; 404 if None
2. `practice_reader.list_exercise_attempts(exercise_id)`; `next_num =
   len(attempts) + 1`
3. `PracticeService()`; `svc.submit_attempt(exercise_id, student_id,
   response_text, next_num)` (pure; `invalid_input` returns without writes)
4. If status != `invalid_input`:
   a. `practice_writer.save_exercise_attempt(attempt)` (WRITE 1; independent
      commit; exactly once)
   b. `try`:
      - `practice_reader.get_practice_target(existing["practice_target_id"])`
      - if target has `source_submission_id`:
        `practice_submission_reader.get_submission_bundle(...)` for source
        text (missing bundle -> empty source text)
      - `svc.evaluate_attempt(attempt, target or {}, source_text)` (pure)
      - `attempt["evaluation"] = practice_writer.save_practice_evaluation(...)`
        (WRITE 2; independent commit)
   c. `except Exception:` `attempt["evaluation"] = None` (swallowed; the
      committed Attempt is authoritative)
5. Return `attempt` (unchanged response shape; evaluation nested or None)

Other write endpoints: `create_practice_target` and `create_exercise` each
perform exactly one Practice write (skipped on `practice_not_available`), one
independent commit, no combined transaction.

## 10. All best-effort branches

- Evaluation generation failure (any exception inside the `try` block,
  including target/bundle reads): swallowed, `attempt["evaluation"] = None`,
  Attempt stays committed, response still returns the attempt.
- Invalid-input attempt: zero writes, attempt dict returned.
- Missing Exercise Instance / Practice Target: 404 before any write.
- Missing Submission Bundle inside evaluation: `source_text = ""` (no error),
  evaluation proceeds.
- No baseline logging or translation exists in the evaluation branch; none is
  added.

## 11. Partial-commit failure matrix

1. Failure before Attempt persistence (missing exercise instance, invalid
   input): zero Attempt rows, zero Evaluation rows, zero later persistence
   calls, baseline 404/response preserved.
2. Failure in Attempt persistence: no committed Attempt; no Evaluation
   generation/persistence; exception propagates (HTTP 500 translation
   unchanged).
3. Failure after Attempt persistence before Evaluation persistence (evaluation
   generation or reads fail): Attempt committed and queryable; Evaluation
   absent; no compensation/retry; response returns attempt with
   `evaluation: None`.
4. Failure in Evaluation persistence: Attempt committed and queryable;
   Evaluation row absent; no Attempt deletion/rollback; `evaluation: None`.
5. Full success: exactly one Attempt write then exactly one Evaluation write;
   response unchanged.

## 16. Database/provider isolation plan

Every write-capable run uses `PYTHON_DOTENV_DISABLED=1`, `DATABASE_URL`
absent, `DATABASE_PATH` inside a fresh unique temporary directory,
`LLM_PROVIDER=local`, resolved-path assertions, development-database
SHA-256/size/mtime checks before and after (never opened), cleanup, and
port-free checks, via the F6D isolation runner (F6C runner pattern; allow-list
= accumulated F2-F6D approved diff: F6C entries plus `app/practice/ports.py`
and `app/api/routers/practice.py`; no wildcards). Practice tests use isolated
persistence paths and deterministic domain inputs; no live external calls.

## 17. Rollback plan

If a focused check fails, identify the smallest affected Port/dependency/
endpoint/branch, reproduce with one focused test, compare against the Phase 0
source-derived sequences, repair only that seam, rerun focused verification,
and only then run the full suite. If completion requires any repository/SQL/
transaction/API/schema change, a shared transaction, moving write
orchestration into `PracticeService`, a new Practice writer workflow, or the
development database, stop and create
`docs/development/BLOCKER_REPORT_V0.9.5_F6D.md`.

## 18. Stop conditions

Stop and create the blocker report if completion requires: changing a
Repository implementation, SQL, an existing transaction boundary, combining
Attempt and Evaluation persistence, a shared transaction, compensation or
retry, moving write orchestration into `PracticeService`, a facade method or
constructor change, API paths/schemas, a compatibility fallback, a proxy/
Service Locator/Unit of Work/DI framework, a missing Practice writer
workflow, the WTR collision fix, live external calls, opening or writing the
development database, or beginning v0.9.5-G. Also stop if `PracticeService`
actively uses persistence, the Router calls a third Repository owner, an
active caller cannot be updated constructor-only, Evaluation failure semantics
cannot be preserved within scope, or source reveals Attempt and Evaluation
share one Repository transaction.
