# v0.9.5-F4 Specification — Reanalysis and Journey Dependency Narrowing

**Date:** 2026-08-02
**Status:** ACTIVE — blocker resolved by owner's two-line operational-script
exception (see `BLOCKER_REPORT_V0.9.5_F4.md`)
**Baseline:** `256b172` (v0.9.5-F3 verification); F2 `7927ca7` and F3
`a24312a`/`256b172` are ancestors.

## Objective

Behavior-preserving Service dependency refactor. Narrow `ReanalysisService`
to one explicit Submission bundle read Port plus one explicit Analysis run
write Port. Narrow `JourneyService` to one explicit Student lookup Port plus
one explicit Journey projection read Port. Move `JourneyService` construction
out of the router into the application composition root. Reuse the existing
facade-owned aggregate repository instances. Preserve all current API,
persistence, transaction, output, error, and UI behavior.

## Reanalysis transaction-preservation rule

`get_submission_bundle` remains a read-only repository connection;
`save_analysis_run` remains an independent Analysis repository transaction.
The Service performs exactly one bundle read and, on the successful path,
exactly one Analysis save. Missing-bundle and analyzer-failure paths perform
zero writes. No shared transaction, no retry, no atomicity between the two
calls. Generated IDs, timestamps, analyzer invocation, and returned shapes
unchanged.

## Journey read-only rule

JourneyService performs zero writes; all nine methods are read-only
projections. Student-not-found raises `LookupError("Student not found.")` as
before. Response shape, section names, ordering, empty-state behavior,
filtering, limits, timestamps, IDs, derived statuses, and error behavior
unchanged. No caching.

## App-state and API dependency design

Both application-construction paths (`_run_startup`, `_build_full_app` in
`app/api/main.py`):

1. extract `repository._submission_repository`, `repository._analysis_repository`,
   `repository._learner_repository`, `repository._practice_repository`
   (private facade access allowed only in the composition root);
2. construct `ReanalysisService(submission_reader, analysis_writer, analyzer)`;
3. construct `JourneyService(student_reader, projection_reader)`;
4. store the JourneyService on `app.state.journey_service`;
5. the Journey router uses `Depends(get_journey_service)` from `app/api/deps.py`
   and no longer receives or constructs from `Database`.

Only the composition root may access facade-owned private repository
attributes. No private access in Services, routers, dependency helpers, or
domain modules. URL, method, schema, status code, and response body unchanged.
Analysis and CALF routers keep consuming `api.state.reanalysis` unchanged.

## Database-isolation plan

Every process capable of constructing `Database` runs with
`PYTHON_DOTENV_DISABLED=1`, `DATABASE_URL` removed, `DATABASE_PATH` set to a
fresh path inside a unique temporary directory, `LLM_PROVIDER=local`; the
effective path is resolved and printed, asserted inside the temporary
directory, asserted not to be the development database or any backup, and
asserted to start in the expected fresh state. After the run, connections and
processes are closed, the temporary directory is removed, ports are verified
free, and the development database SHA-256 and mtime are rechecked (must be
unchanged; it is never opened).

## Rollback plan

All changes are reversible through the two focused commits
(`refactor(v0.9.5-f4): ...`, then `test(v0.9.5-f4): ...`); `git revert` of
either commit restores the previous behavior. No schema, SQL, or data
migration is touched, so no database rollback is required.
