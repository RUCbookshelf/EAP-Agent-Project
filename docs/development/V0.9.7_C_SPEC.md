## 1. WU1 - Journey Cycle Model and Completion State

### 1.1 Objective

A learner-owned, read-only Journey cycle/view model that groups the existing
raw Journey events into coherent writing and Practice cycles with honest
student-facing states. No writes, no new raw events, no migration.

### 1.2 Implementation notes (targeted reconnaissance, WU1)

- Raw projection: `JourneyService.get_journey` (app/journey/service.py)
  reads eight learner-scoped record sets (now nine: exercises were added
  for attempt->target association), derives 12 raw event types, sorts,
  deduplicates, and classifies state. Raw contract unchanged.
- Persisted relationships used by the cycle model:
  - revision root: `essays.revision_of_submission_id` chain (plus
    `revision_group_id`/`revision_sequence` when present);
  - feedback: `feedback_records.essay_id` (INTEGER, unique per essay);
  - target provenance: `practice_targets.source_submission_id` +
    `target_json.source_priority_id` (`PRIO-{feedback_id}-{index}`);
  - attempt -> target: `exercise_attempts.exercise_id` ->
    `exercise_instances.practice_target_id`;
  - evaluation -> attempt: `practice_evaluations.attempt_id`.
- Priority provenance is validated read-only by parsing the stable
  reference (app/practice/mapping.py::parse_stable_priority_reference) and
  checking the persisted feedback record + index. Legacy (no reference)
  and unresolved references never gain fabricated provenance.
- The verified pipeline always creates analysis + feedback together; a
  submission without an analysis record maps to `insufficient_evidence`
  (matching the raw event vocabulary). The `submitted` base state is
  reserved in the vocabulary; the most informative state takes precedence.

### 1.3 Cycle view model (additive response)

`GET /api/v1/students/{id}/journey` keeps its existing fields and adds two
additive keys:

```text
cycles: JourneyCycle[]          # parallel read-only view
cycles_version: "journey-cycle-v0.9.7-c"
```

```text
JourneyCycle
├── cycle_id                    # "cycle-{anchor_essay_id}" (or
│                               #  "cycle-unlinked-practice")
├── learner_id
├── relationship_status         # linked | unlinked
├── root_submission             # JourneySubmissionView | None
├── revisions[]                 # JourneySubmissionView[]
├── feedback_stages[]           # JourneyFeedbackStage[]
├── practice_cycles[]           # JourneyPracticeCycle[]
├── current_state               # most advanced honest stage
├── chronology[]                # raw events of this cycle, raw order
├── available_actions[]         # empty in WU1; populated by WU2
└── limitations[]
```

```text
JourneyPracticeCycle
├── practice_target             # id/code/label/status/timestamps
├── source_submission_id
├── priority_provenance         # {status: valid|legacy|unresolved, ...}
├── exercise | None
├── attempt | None              # latest persisted attempt
├── evaluation | None
├── activity_state              # available | attempted |
│                               # evaluation_available |
│                               # evaluation_unavailable | completed |
│                               # unavailable (unsupported status)
├── evaluation_state            # not_applicable | unavailable | available
└── completion_state            # active | completed
```

### 1.4 Writing states

Per-submission `writing_state` (most informative, persisted activity only):

| State | Derivation |
|---|---|
| `revision_submitted` | essay has `revision_of_submission_id` |
| `insufficient_evidence` | root essay without an analysis record |
| `analyzed` | analysis exists, no feedback record |
| `feedback_without_priority` | feedback exists, zero priority items |
| `feedback_available` | feedback exists with priority items |
| `submitted` | base record state (reserved fallback) |

### 1.5 Practice activity states

| `activity_state` | Derivation (precedence) |
|---|---|
| `completed` | target status `completed` (evaluation may still be unavailable) |
| `evaluation_available` | attempt + persisted evaluation (active target) |
| `evaluation_unavailable` | attempt, no evaluation (active target) |
| `attempted` | attempt on a non-active, non-completed target |
| `available` | active target, no attempt |
| `unavailable` | unsupported status, no attempt (defensive) |

Attempts are authoritative saved work; evaluation unavailable never implies
failure, non-completion, or missing mastery. Completion is activity
completion only.

### 1.6 Grouping rules

- Cycle anchor = root submission resolved through persisted revision
  linkage; broken chains become controlled `unlinked` cycles (no
  cross-association, stable limitation).
- Independent essays => independent cycles (ordered by root submitted_at,
  then root essay_id).
- Practice attaches to the cycle whose submissions include the target's
  `source_submission_id`; unresolvable targets form the controlled
  `cycle-unlinked-practice` group.
- Cycle `current_state` = most advanced state among root writing state,
  revision states, and practice activity states (stable order documented
  in app/journey/cycles.py).
- `chronology` = the cycle's raw events in the existing raw ordering
  (submission anchor -> stage -> source id -> event type); deduplication
  keys remain unique.
