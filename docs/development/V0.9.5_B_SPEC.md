## 3. Canonical health decision

- Exactly one `GET /api/v1/system/health` handler, based on the **lifecycle representation** (`app.lifecycle.lifecycle.health_dict()`), moved into `routers/system.py`.
- The duplicate business health handler (live `repository.ping()` semantics) is **removed**; no alias or second endpoint is created.
- Production (`create_app()`) and test (`create_app(settings)` / `_build_full_app`) builders include the same system router, so registration order can no longer change health semantics.
- `/system/live` and `/system/ready` handlers are preserved unchanged.
- The unreachable duplicate lifecycle-route block after `return` in `create_app` is removed.
- Health contract (one registration, prod/test parity, healthy and unavailable states, request ID, error envelope, live/ready unchanged) is pinned by new tests in `tests/test_v095b_router_contract.py`.

## 4. Files expected to change

Production:
- `app/api/main.py` — becomes the composition root (app creation, lifespan, middleware, error handlers, service construction, router inclusion; no feature handlers).
- `app/api/routers/__init__.py` — new, re-exports routers.
- `app/api/routers/{system,submissions,analysis,students,revisions,practice,journey,research,calf,admin}.py` — new, feature-owned route handlers.
- `app/api/deps.py` — new, API-only helpers (app-state accessors, `require_student`) required to register routers.

Tests:
- `tests/test_v095b_router_contract.py` — new contract tests (route inventory, health semantics, prod/test parity).

Verification (this stage):
- `verification/v0.9.5-b/capture_route_inventory.py` and `route_inventory_before.json` (pre-change evidence).

Documentation:
- `docs/development/V0.9.5_B_SPEC.md` (this file), `RUN_VERIFICATION_V0.9.5_B.md`, minimal entries in `CHANGELOG.md`, `PROJECT_STATE.md`, `docs/development/MASTER_ROADMAP.md`, `docs/development/CURRENT_TASK_STATE.md`, `docs/development/DECISION_LOG.md`.

## 5. Explicit non-goals

No change to: Streamlit pages/components/tokens/localization, `app/ui/api_client.py`, API request/response schemas, services, domain algorithms, repository protocols, `Database`, SQL, migrations, table ownership, configuration behavior, retry/timeout behavior, request IDs, error taxonomy, Diagnostic Gate, CALF, Practice, Revision, Journey, research-export, authentication, external providers.

Deferred (not part of v0.9.5-B): version constants (`0.8.0`), UI imports of backend schemas, endpoint↔client parity for the 22 unwrapped endpoints, `export_jobs` writer, WTR ID allocation, duplicated repository protocols, Database god-class, page monoliths, test-pyramid imbalance, sync-conflict files, legacy `FeedbackPipeline`.

## 6. Behavior-preservation checks

- Every pre-change path+method remains; no unintended path+method is added; no duplicate path+method remains; `/api/v1/system/health` appears exactly once.
- Route names, operation IDs, response models, and declared status codes are preserved (handler function names are unchanged; FastAPI dependency parameters do not appear in OpenAPI).
- Production and test builders expose identical route sets.
- Health handler is the only intentional semantic reconciliation (lifecycle-based).
- Services, repositories, database schema, and UI are untouched; `git diff` for this stage covers only the allowed file list.

## 7. Rollback plan

The implementation commit is isolated and no history is rewritten. Rollback = `git revert <implementation-commit>` (or `git reset --hard <baseline>` on a clean local state), followed by rerunning `tests/test_v095b_router_contract.py` and the Phase 0 targeted API tests to confirm the pre-change surface is restored.
