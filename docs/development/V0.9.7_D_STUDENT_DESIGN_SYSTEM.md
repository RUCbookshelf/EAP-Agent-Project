**Baseline:** branch `master`, HEAD `6a2e927` (v0.9.7-C closure);
migration 13; config-v0.9.0; locale parity 600/600.
**Sources:** design consultation A (`kimi_proposal_a.md`, kimi-k3 via the

## 1. Product visual direction

**"Calm ledger"**: a quiet record-keeping workspace for academic writing
learning. White page, ink structure, tinted state washes, and one red
reserved for forward action. Pixel identity is retained as *structural
crispness* (square corners, solid fills, hard offset shadows on
interactive surfaces) and demoted from arcade loudness to an
editorial-technical register. Monospace survives only where it carries
meaning: IDs, references, versions, metrics.

Intended tone: calm, credible, focused, supportive without being
childish; polished without decorative excess; a place where the learner
trusts what they read because nothing is shouting.

## 2. Design principles

1. Comprehension before decoration - every visual element carries state
   or structure.
2. Quiet by default, loud by exception - states use tinted surfaces;
   solid saturated fills appear only on the single primary action.
3. One loud thing per view - one primary action and at most one focused
   panel per page region.
4. Hierarchy through spacing, border weight, and typography - not through
   more colors.
5. Shared rules over page-specific styling - every rule defined once,
   reused across all Student pages.

## 3. Semantic tokens (canonical source: `app/ui/pixel_art.py`)

Base neutrals (kept): background `#ffffff`, primary surface `#ffffff`,
secondary surface `#f4f4f4`, elevated surface `#ffffff` + shadow-md;
text `#1a1c2c`, text-secondary `#4a4a58`, muted `#6b6b7b`, border
`#1a1c2c`, focus `#0f6dbd` (3px outline, 2px offset).

Added: `border-subtle` `#8a8a9c` (hairlines, nested-item outlines,
metadata separators; 3.39:1 on white, 3.08:1 on surface).

Action tokens (kept + added):
- primary action `#e00047` / white text (4.93:1) - reserved for forward
  actions only (never nav selection, badges, category titles, or
  decorative blocks);
- secondary action `#f4f4f4` / `#1a1c2c` with 2px ink border;
- tertiary/text action link `#0f6dbd`, no fill;
- destructive (reserved, no consumer yet) `#a30d3d` on tint `#fdeaef`
  (6.78:1), always paired with a confirmation pattern;
- disabled `#e8e8ec` / `#5a5a68` (5.55:1), no shadow, reason in helper
  text when non-obvious;
- `pixel-red #ff004d` remains decorative-only, non-text.

Quiet semantic states (fills/on-* reassigned; accents added) - every
state surface carries a tinted background, a 4px left accent bar, a local
SVG icon, and a bold localized label:

| State | Tint fill | Accent | Label text | Icon | Label contrast |
|---|---|---|---|---|---|
| informational | `#e8f3fb` | `#0f6dbd` | `#0b4f86` | info | 7.53:1 |
| success / completed | `#e6f6ec` | `#1c7a45` | `#14532d` | check | 8.14:1 |
| warning / attention | `#fdf6d8` | `#a16207` | `#713f12` | warning | 7.99:1 |
| error | `#fdeaef` | `#c01048` | `#a30d3d` | error | 6.78:1 |
| neutral / unavailable / insufficient | `#f4f4f4` | `#6b6b7b` | `#4a4a58` | per state | 7.92:1 |

Retained as-is: `selected` and `candidate` neon values (Research-only
metric cards; Research redesign is out of scope; token-level inheritance
is verified by Research smoke).

Product-state recipes (never color alone):
- active Practice: info tint + 2px `#0f6dbd` border on the stage item +
  info badge;
- evaluation unavailable: neutral tint + dashed 2px `#6b6b7b` border +
  clock icon + existing localized text (never error red);
- legacy/unlinked/unresolved provenance: neutral tint + dashed border +
  info icon + explicit provenance text;
- submitted/completed confirmations: success tint notice on save; success
  badge on the stage item on later renders;
- no priority / insufficient evidence: neutral tint + info icon (outcomes,
  not errors);
- limitation/disclaimer notices: neutral or warning tint, wording
  untouched.

## 4. Typography hierarchy

Local/system font stacks only (no remote fonts).

| Role | Stack | Size / weight / line-height |
|---|---|---|
| page title | sans display | 1.625rem / 700 / 1.25 (h2 role; sizes ride the existing scale) |
| page introduction | sans | 1rem / 400 / 1.6, text-secondary |
| section heading | sans display | 1.25rem / 700 / 1.3 |
| card title | sans display | 1.0625rem / 600 / 1.35 (new card-title size + semibold weight) |
| body | sans | 1rem / 400 / 1.6 |
| metadata | sans | 0.875rem / 400 / 1.5, muted |
| helper text | sans | 0.875rem / 400 / 1.5, muted |
| status label | sans | 0.8125rem / 700 / 1.4 |
| button text | sans | 1rem / 700 (primary), 1rem / 600 (secondary/tertiary) |
| technical / mono | mono | 0.875rem / 400 (IDs, references, version, metrics) |

Key decision: `--px-font-heading` is re-pointed from mono to the sans
display role (one canonical line), so Chinese headings render in
Noto Sans SC / PingFang SC / Microsoft YaHei. Mono remains deliberately
used for technical roles (`.px-badge`, `.px-mono`, code, metrics,
`cycle-*` IDs, `Submission #n` references) and never wraps zh prose.

Readability: body line length <= ~75 characters (720px student column);
line-height 1.6; no justified text; no negative letter-spacing; no
uppercase transforms (they break Chinese); mono on Latin/digit runs only.

## 5. Spacing and sizing scale

4px-base scale kept and role-assigned (no literal pixel margins/paddings
in components):

| Role | Token | Value |
|---|---|---|
| micro (icon gaps, badge padding) | `--px-space-1` | 4px |
| inline (label-value, icon-text) | `--px-space-2` / `--px-inline-gap` | 8px |
| control gap | `--px-space-3` | 12px |
| card padding (default) | `--px-card-pad` | 16px |
| card padding (student alias) | density `student-card-pad` | 20px |
| section spacing | `--px-section-space` | 32px |
| page spacing | `--px-page-space` | 40px |

Controls: 40px desktop / 44px mobile as `min-height` (labels may wrap to
two lines); touch targets >= 44x44px; >= 8px separation between adjacent
targets. Geometry: radius 0 everywhere; 4px borders reserved for state
accent bars, the focused panel, and structural rules; 2px for
cards/buttons/notices/inputs; 1px hairline (`border-subtle`) for nested
items and metadata separators; shadows sm (2px) on interactive cards and
buttons, md (4px) on the focused panel, lg unused on Student pages; icon
sizes 16/20/24px (badges/notices/empty states).

## 6. Surface hierarchy

| Level | Name | Recipe | Use |
|---|---|---|---|
| L0 | plain page section | bg, no border | page canvas, direct prose |
| L1 | subtle container | surface, 1px border-subtle or none, pad 16 | context/metadata blocks, purpose block |
| L2 | primary card | white, 2px ink border, shadow-sm, pad 20 | cycle cards, priority cards, state panels |
| L3 | nested stage item | white, 1px border-subtle, no shadow, pad 12/16 | stage items inside L2 |
| notice | state tint | tint + 4px accent bar + icon + label + body | all state/limitation messages |
| empty | absence | L0/L1 + optional dashed 1px border-subtle, muted icon | absences with next step |
| focused panel | act-here | elevated, 4px ink border, shadow-md, pad 20 | single current action block |

Nesting rules: max L0 -> L2 -> L3; a bordered surface never sits inside
an L3; notices attach to L1/L2, never inside L3 content; one focused
panel per page; L3 items in one L2 share one recipe; no shadows on nested
levels.

## 7. Action hierarchy

- Primary: solid `#e00047` fill, white text; exactly one per page view.
- Secondary: surface fill, 2px ink border; default rank for record-level
  actions (Open Revision / Open Practice on Journey).
- Tertiary/text: link blue, no fill; reserved for low-stakes inline
  affordances (none newly introduced).
- Destructive: reserved deep-red token; requires confirmation; isolated
  >= 24px from other actions.
- Disabled: `#e8e8ec` / `#5a5a68`, no shadow, reason when non-obvious.
- Pending: action becomes disabled + unified loading indicator adjacent
  to the action row; button wording never changes.

Placement: actions live at the end of the block they act on; page-level
primary CTA sits in the next-step action block after content and before
the limitation notice. On Journey, each stage item carries at most one
action - rendered as one full-width secondary button (Streamlit columns
risk 390px overflow; the existing matrix asserts no overflow). Below
640px all actions stack full-width.

## 8. State system

See ST-01 matrix in the consultation record: active, completed,
submitted, feedback available, no priority, insufficient evidence,
evaluation unavailable, legacy/unlinked, loading, empty, recoverable
error, blocking error - each with surface/border recipe, icon, badge,
text channel (existing localized wording), and action rules. Badge text
always comes from existing localized state labels (wording frozen).

Combination rules: one status badge per stage item; at most two notices
inside one stage item; status text present whenever an icon is present;
co-occurring sub-states (e.g., completed with evaluation unavailable)
report record state in the badge and sub-state in the notice - no merged
or invented states.

## 9. Shared component specifications

Implemented from the existing primitives in `app/ui/components.py` +
`pixel_art.py` (no speculative layer):

- **Page header** (`student_page_intro`/`page_header`): title (sans
  display) + introduction; 8px title-intro gap; optional disclaimer
  beneath.
- **Section header** (`section_header`): heading + full-width 1px
  border-subtle rule; 32px above / 16px below.
- **Status badge** (`status_badge`): 16px icon + localized label; tint
  bg + 1px accent border; `data-testid="px-status-badge"` +
  `data-state`; sans label; one badge per item.
- **Action row** (pattern + CSS class): grouped actions at block end,
  primary -> secondary -> tertiary, stacked full-width < 640px.
- **Notice** (`notice()` core; `warning_box`/`info_box`/`success_box`/
  `error_box`/`limitation_notice` remain as wrappers): tint + 4px accent
  bar + 20px icon + bold label + body; dashed variant for
  unavailable/legacy; no full-bleed neon.
- **Empty state** (`empty_state`): muted 24px icon + message + optional
  secondary action.
- **Error state** (`render_api_error`): error-tint notice; recoverable
  variant shows its recovery action, blocking variant shows explanation
  + reference only.
- **Metadata row** (`student_context_block`): L1 container; label
  column content-sized (max 45%), value wraps; 1px border-subtle
  hairline between rows.
- **Record reference** (`technical_caption`): mono compact muted text;
  optional sans prefix label; wraps instead of truncating.
- **Cycle card** (Journey): L2 card; header row = card title +
  record-reference chip (`cycle-{id}`) + cycle-stage badge; body =
  ordered stage items; 24px between cards.
- **Stage item** (Journey): L3 inset block; top row = stage label +
  status badge (reflows at narrow widths); <= 2 metadata rows; notices;
  one secondary action.
- **Practice state panel** (Journey): stage-item variant with state-driven
  notice/badge per section 3 recipes (six Practice states).

## 10. Journey reference composition

Page header -> disclaimer notice (quiet info) -> learner context (L1) ->
writing-cycle cards (existing frozen order: Original, Revised with
"Revision of #n", feedback stage, Practice activity; unlinked warning on
its card) -> next-step action block (single primary) -> limitation
notice. Stage items: badge top-right; state detail as quiet notice;
actions secondary; <= 2 metadata rows; provenance/references as record
references. Variants: empty (CP-06 with existing next-step wording),
loading (unified loading box), error (recoverable/blocking). Cycles stay
expanded (collapsible cycles deferred).

## 11. Bilingual rules

No fixed widths/heights on text containers; controls use min-height;
buttons, badges, metadata labels, and notice bodies wrap; metadata label
column content-sized; mixed technical references keep mono IDs inline in
zh prose; all grids reflow at 390px. zh renders in sans everywhere
including headings, badges, and status labels; no uppercase, no
letter-spacing, no case transforms; en sized with ~30% growth headroom.

## 12. Streamlit implementation constraints

Stable `data-testid` and documented stable classes only; never hashed
classes; single canonical token source `pixel_art.py`; generated CSS
(`PIXEL_CSS`, `PIXEL_COMPONENT_CSS`); no literal hex outside
`pixel_art.py`; no remote resources; no `!important` proliferation;
`.streamlit/config.toml` parity preserved (`#e00047`, `#ffffff`,
`#f4f4f4`, `#1a1c2c`, sans serif - theme values unchanged).

## 13. Prohibited patterns

Neon full-bleed banners; gamified solid step tiles; gradients;
glassmorphism; soft shadows; rounded corners; badge walls; color-only
state signaling; emoji as icons; icon-only critical actions; marketing
hero blocks; decorative animation; per-page ad-hoc hex values; uppercase
or letter-spaced Chinese; text embedded in decorative images; remote
assets of any kind.

## 14. Accessibility baseline (v0.9.7-D)

All text pairs >= 4.5:1 (section 3 table is the contract); focus outline
>= 3:1 against adjacent surfaces; state borders >= 3:1; every state
surface has icon + text channels; touch targets >= 44px; visible focus
rings; role/aria on meaningful icons; motion disabled + reduced-motion
block preserved. Full accessibility remediation beyond these criteria is
deferred to v0.9.7-E.
