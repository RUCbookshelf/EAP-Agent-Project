# v0.5 SPEC — Revision-aware Feedback

Status: `not_started` until v0.4 passes.

## Required outcome

Create explicit, validated revision relationships and Revision Groups. Implement local, transparent paragraph → sentence → token/lemma alignment; observed metric changes; revision comparability; diagnosis trajectories; cautiously worded feedback-uptake candidates; and append-only Revision Snapshots. Add the required API and Streamlit workflow while keeping within-task revision evidence separate from cross-task longitudinal evidence.

## Invariants

- Same prompt/student never creates a relationship without explicit confirmation.
- Reject cross-student, self, cyclic and duplicate links; preserve original draft-stage audit data.
- Alignment and uptake are local versioned candidates, not causal or proficiency claims.
- One representative draft per Revision Group enters default long-term trends (final, otherwise latest).
- DeepSeek receives only locally generated revision evidence and must cite allowed evidence IDs.
- Reanalysis appends; no essay, AnalysisRun, feedback or Snapshot is overwritten.

## Acceptance evidence

Tests cover all 40 numbered v0.5 cases and all earlier suites, plus FastAPI, Streamlit, migration, persistence and `run.bat`. Documentation deliverables include `docs/REVISION_ANALYSIS.md`, `docs/FEEDBACK_UPTAKE.md`, `RUN_VERIFICATION_V0.5.md`, and `docs/development/V0.5_HUMAN_REVIEW_GUIDE.md`.
