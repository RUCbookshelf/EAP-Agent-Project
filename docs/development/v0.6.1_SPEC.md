# v0.6.1 SPEC — Diagnostic Calibration

Status: `completed` on 2026-07-29. Authorized scope ends after v0.6.1; v0.7 and full CALF remain `not_started`.

## Outcome

Insert a deterministic, versioned calibration layer between automatic analysis and feedback:

`AnalysisResult → Metric Confidence → raw diagnosis candidates → Diagnostic Gate → Evidence Relevance → Priority Score → selected DiagnosisResult → FeedbackContext`.

Metrics and suppressed signals remain append-only research evidence. Only selected, evidence-verified priorities reach student feedback or exercise generation.

## Frozen engineering decisions

- Application `0.6.1`; migration `7`; Analyzer `spacy-analyzer-v0.6.1`; Diagnosis/Gate/Priority `v0.6.1`; Prompt/Schema `v0.6.1`.
- Migration 7 adds append-only diagnostic calibration audits. Existing essays, AnalysisRuns, metrics, diagnoses, feedback, revision and learner snapshots are preserved.
- Because `config-v0.6.1` already exists, migration 7 creates and activates `config-v0.6.2`, with `config-v0.6.1` retained as its inactive parent.
- Metric confidence and diagnosis confidence are separate typed fields. Confidence is never inferred from metric magnitude alone.
- New lexical metric versions use alphabetic spaCy tokens. Displayed word/type counts and TTR use lowercase surface forms; lemma frequencies are separately labelled lowercase lemma evidence.
- New AnalysisRuns emit only the latest metric version per metric ID. Old definitions/results remain registered/readable, and dashboards keep versions in separate segments.
- Diagnostic calibration is deterministic local code. No LLM scoring, embedding service, CEFR, overall score, CALF total, complete T-unit analysis, or automatic grammar-error count is introduced.
- Zero selected priorities and zero exercises are valid. No filler diagnosis is added.
- A positive finding must be a verified textual observation. If no reliable strength is available, LocalDemo and Prompt use a neutral, exact-text observation rather than converting length or parser counts into quality.
- Connective non-detection is not a cohesion diagnosis. A connective priority requires a specific adjacent-sentence or paragraph-boundary location; otherwise it remains monitored/suppressed.
- One configured correction retry remains. Its 3,600-token budget and all existing quote, ID, Pydantic, redaction and fallback safeguards remain unchanged.

## Data contracts

Each MetricResult records measurement status, confidence, reasons, risk factors, diagnostic and longitudinal eligibility, limitations, and reproducible measurement metadata.

Each calibrated signal records signal/source IDs, gate rule/version/result, exclusion reasons, metric and diagnosis confidence, evidence relevance, priority score/components, selection status/reason, and safe evidence metadata. States are `raw_signal`, `monitored_signal`, `eligible_diagnosis`, `selected_priority`, `suppressed`, and `insufficient_evidence`.

Calibration audits are saved separately and exposed through a read-only submission audit API. Student responses expose only selected diagnosis/feedback; the local researcher page exposes the full audit.

## Conservative default rules

- Maximum selected priorities: 2.
- Repetition: minimum count 4 and density 0.025 unless a verified local cluster exists. Count 3 without a local cluster remains monitored. Prompt keywords and necessary/task-term candidates receive penalties.
- Connectives: resource v0.6.1 records discourse, coordination, subordination and paragraph-organization classes. A specific verified location is mandatory for priority selection.
- Exercises: high confidence ≤3, medium ≤2, low ≤1; monitored/suppressed signals receive none.
- Priority score uses explicit evidence strength, metric confidence, diagnosis confidence, local concentration/magnitude, actionability, pedagogical value, history relevance, evidence verification, redundancy and penalties. Thresholds are configuration values and unvalidated working assumptions.
