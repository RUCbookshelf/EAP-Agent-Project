## 3. Canonical Error Taxonomy

Module `app/errors.py` defines `ErrorCategory`, `ApiError`, message keys,
default HTTP statuses, and retryability.

Categories: service_not_running, service_starting, service_degraded,
service_failed, request_timeout, connection_interrupted, resource_not_found,
invalid_request, backend_processing_error, invalid_response,
provider_unavailable, permission_or_privacy_rejection,
conflict_or_duplicate_request, unknown_error.

Public error body: {error: {category, message_key, operation, request_id,
http_status, timestamp, retryable, detail, field_errors}}.

Retryable categories (automatic retry allowed ONLY for idempotent GETs):
service_starting, connection_interrupted, request_timeout.

## 4. Server-Side Mapping

- RequestValidationError -> 422 invalid_request with field errors.
- HTTPException 404 -> resource_not_found; 422 -> invalid_request; 409 ->
  conflict_or_duplicate_request; 403 -> permission_or_privacy_rejection;
  503 -> service_degraded; others -> backend_processing_error.
- Unexpected exceptions -> 500 backend_processing_error, logged with
  request_id; sanitized public detail.
- Exception handlers are registered at app creation (both production lifespan
  app and test app) so the middleware stack includes them.

## 5. Request Correlation

- Middleware generates/accepts X-Request-ID, sets request.state.request_id,
  adds the response header, and logs a sanitized request line:
  request_id, method, route path, status, elapsed_ms, lifecycle state.
- Error bodies include request_id.
- Request IDs are random; never derived from learner or submission IDs.

## 6. Client-Side Classification

`app/ui/api_client.py` classifies connect vs read timeouts, connection
refused, interrupted connections, HTTP 4xx/5xx via the canonical error body,
and malformed responses (invalid_response). lifecycle_state() distinguishes
starting from absent. Timeout profiles are centralized in TimeoutProfile:
connect 2s, read 10s, write 30s, long-read 60s; lifecycle 5s read.

## 7. Retry and Idempotency Policy

- Automatic retry: at most 1 retry, GET only, only for retryable categories.
- No automatic retry for POST/PUT/PATCH/DELETE.
- Human reviews get stable HR ids; export jobs use EXP ids; writes are
  append-only via INSERT OR REPLACE on generated ids.

## 8. Role-Appropriate Presentation

- Research/System Audit: category, operation, request ID, HTTP status,
