## Root cause (proven in DP0-A)

`deepseek-v4-pro` defaults to thinking mode (official docs). The production
request omitted the toggle, so every structured-feedback request ran in
thinking mode: reasoning tokens consumed 1300 of the 1800-token output
budget (72%), the JSON truncated (`finish_reason=length`), and the router
correction attempt exceeded the 30-second transport timeout. Result:
LocalDemo fallback on every preflight submission (D0 evidence).

## Approved repair (Gate-1 accepted by the owner)

```text
1. app/llm/deepseek.py: payload now sends thinking={"type": "disabled"}
   for the DeepSeek structured-feedback request path only.
2. Preserved: deepseek-v4-pro; feedback-prompt-v0.7.1; StructuredFeedback
   schema; Diagnostic Gate thresholds and priority rules; max-token
   behavior; correction and fallback policy; 180s frontend timeout.
3. Sanitized provider metadata capture: response id, returned model,
   finish reason, prompt/completion/total/reasoning tokens, requested max
   tokens, content length, request duration, JSON parse status,
   schema-validation status (plus existing correction/fallback status).
4. finish_reason=length is classified explicitly as
   provider_output_truncated; malformed JSON is classified as
   provider_json_invalid before schema validation.
5. Truncated/malformed/incomplete JSON continues to be rejected; no
   bracket repair, no validation weakening, no silent field repair.
```

Timeout decision (owner-directed): the 30-second provider timeout was kept
for the first post-fix verification; durations were recorded on every live
request (max 21.7s), so no timeout increase was needed.
