# v0.9.5-G Specification - Database Facade Contraction

**Date:** 2026-08-03
**Status:** ACTIVE
**Baseline:** `eacf76b` (v0.9.5-F6D verification); F2-F6D commits are
ancestors. Branch `master`, HEAD `eacf76b`.
**Authorization:** Owner-authorized v0.9.5-G stage (pasted instruction file).
**Full-core baseline:** 638 passed, 8 skipped (equals the completed F6D
verification value at HEAD `eacf76b`).

## Objective

Behavior-preserving architecture contraction: migrate every remaining active
caller of the 86-method `Database` public facade to existing facade-owned
aggregate Repositories, Services, or new exact API Ports; contract the public
surface to the smallest evidence-supported infrastructure/lifecycle set;
resolve the `SQLiteRepository = Database` alias; keep `Database` as the sole
owner of one `SQLiteConnectionManager` and one Repository graph. No Repository
implementation, SQL, transaction boundary, API contract, schema, prompt,
provider, UI, or behavior change.

## 1. Included and excluded components

Included:

- `app/database/repository.py` (public-surface contraction only)
- `app/database/__init__.py` (alias/export resolution)
- `app/api/ports.py` (new: exact API-owned consumer Ports)
- `app/api/main.py` (app-state composition, lifecycle migration)
- `app/api/deps.py` (narrow accessors; `get_repository` removal)
- Remaining production Routers with direct facade usage (`analysis.py`,
  `calf.py`, `research.py`, `revisions.py`, `students.py`, `submissions.py`,
  `system.py`)
- `app/feedback/service.py` (legacy composition migration)
- Active operational scripts and verification helpers with direct facade
  business calls
- Minimal test migration from broad-facade convenience
- One new focused G facade-contraction test file
- Documentation: this SPEC, `RUN_VERIFICATION_V0.9.5_G.md`, minimal
  CHANGELOG/PROJECT_STATE/ROADMAP/TASK_STATE/DECISION_LOG updates
- `verification/v0.9.5-g/` artifacts (before/after facade inventory, removal
  ledger, G-era parity runner)

Excluded (deferred): Protocol consolidation, legacy `SubmissionRepository`
removal, FeedbackPipeline removal, WTR collision, export-job redesign, schema
cleanup, Migration 13, transaction redesign, Unit of Work/compensation/retry,
lifecycle-race fix, CRG tooling repair, UI/localization, v0.9.6 features.

Do not change: Repository implementations, Repository method signatures,
`SQLiteConnectionManager`, SQL, DDL, migrations, table ownership, indexes,
foreign keys, initialization data, prompts, configurations, provider logic,
API paths/methods/models/status codes/error translation, frontend client
methods, or localization.

## 2. Current and target architecture diagrams

Current:

```text
Database (86 public methods, 1:1 business delegation to 9 aggregate Repositories)
  |-- Depends(get_repository) in 7 production Routers (analysis, calf,
  |   research, revisions, students, submissions, system)
  |-- FeedbackPipeline (LearnerHistoryService(facade), record_versions)
  |-- app/api/main.py lifecycle (migration_version, get_active_configuration)
  |-- operational scripts (business calls through the facade)
  `-- tests/verification (broad-facade convenience)
SQLiteRepository = Database alias exported from app/database
```

Target:

```text
Database
  |-- owns one SQLiteConnectionManager
  |-- owns one instance of each aggregate Repository (private fields)
  `-- public surface: connect, initialize (evidence-supported infrastructure)

Composition roots (main.py, FeedbackPipeline, scripts)
  |-- construct Database once, initialize, use private facade-owned
  |   aggregate Repositories
  `-- no broad business delegation

Production Routers
  |-- exact API Ports composed from facade-owned Repositories on app.state
  `-- StudentLookupPort feeds require_student

app/api/deps.py: narrow accessors only (get_repository removed)
```

No RepositoryContainer, ApplicationRepository, DatabasePort,
GeneralRepository, RepositoryRegistry, public bundle, proxy, adapter, Service
Locator, Unit of Work, DI framework, `__getattr__`, or dynamic delegation is
created. No public `get_repository(...)`/`repositories`/`repository_graph`
accessor is added.

## 5. Exact caller migration plan

1. Routers: inject exact API Ports through new `app/api/ports.py` + app-state
   entries + dependency accessors; `require_student` receives
   `StudentLookupPort`; endpoint bodies unchanged otherwise.
2. `app/api/deps.py`: add the narrow accessors; remove `get_repository` after
   all Router migration.
3. `app/api/main.py`: compose the new state entries; migrate the three
   lifecycle business calls to private repos.
4. `app/feedback/service.py`: migrate history reader and `record_versions` to
   private facade-owned repos.
5. Operational scripts and verification helpers: replace public business
   delegation with the exact facade-owned aggregate Repository (private
   composition-root access), preserving CLI, output, exit codes, provider
   behavior, and order.
6. Tests: migrate broad-facade convenience to `database._<owner>_repository`;
   update facade-contract tests to the G-era contract; leave historical E
   inventory JSON untouched.
7. `app/database/repository.py`: remove the 84 delegation methods.
8. `app/database/__init__.py`: remove `SQLiteRepository` alias/export
   (no supported active use remains: definition + one parity-test import).

## 19. Database/provider isolation

Every write-capable run uses `PYTHON_DOTENV_DISABLED=1`, `DATABASE_URL` absent,
`DATABASE_PATH` inside a fresh unique temporary directory, `LLM_PROVIDER=local`,
resolved-path assertions, development-database SHA-256/size/mtime checks
before/after (never opened), cleanup, and port-free checks, via the G-era
isolation runner (F6D runner pattern; allow-list = accumulated F2-G approved
diff, no wildcards). No live external-provider runs; live scripts are
compile/import verified only.

## 20. Rollback plan

If a focused check fails, identify the smallest affected caller or method
disposition, restore or migrate only that seam, update the disposition ledger,
rerun focused checks, and only then run the full suite. If completion requires
Repository/SQL/transaction/API changes, a shared transaction, a public
Repository bundle, a second graph, or the development database, stop and
create `docs/development/BLOCKER_REPORT_V0.9.5_G.md`.

## 21. Stop conditions

Stop and create the blocker report if completion requires: changing a
Repository implementation, SQL/DDL/migrations, a transaction boundary, a
shared transaction or Unit of Work, compensation/retry, API paths/schemas,
Service business logic, a public Repository bundle or generic accessor, a
second Repository graph, FeedbackPipeline redesign, export-job workflow
changes, missing Practice workflows, WTR fix, live external calls, opening or
writing the development database, Protocol consolidation, or any later stage.
Also stop if a public method has an active caller that cannot be migrated
within scope, the alias has an unresolvable supported requirement, final
behavior requires restoring a broad Router dependency, Repository identity
cannot be preserved, or historical E behavior cannot coexist with the
approved G contraction.
