## 5. Structural-satisfaction evidence

For each binding, deterministic `inspect.signature` comparison of every Port
method against the concrete Repository method: method exists; parameter
names, kinds, order, and defaults match. Result: **PASS for all 10 bindings**
(recorded per method in `api_port_bindings_before.json`). Runtime
`isinstance` checks are not used as satisfaction proof.

## 6. Current and target annotations

All ten accessors currently have **no return annotation** (`None` in the
before mapping). Target: the exact API-owned Port as the return annotation
(e.g., `def get_student_lookup(request: Request) -> StudentLookupPort:`).

## 7. Import-direction proof

`app/api/deps.py` will import from `app.api.ports` (api -> api). `ports.py`
imports only `typing` and domain models (`app.calf`, `app.calibration`,
`app.revision`); it imports no API module, so no circular dependency is
introduced. Routers already import `app.api.deps`.

## 8. FastAPI annotation-resolution strategy

Direct `from app.api.ports import <Port>` at module top (no
`TYPE_CHECKING`-only import, no string forward reference). Every annotation
must resolve through `typing.get_type_hints(accessor)["return"]` to the exact
Port class; importing `app.api.deps`, every Router, and both application
construction paths must succeed.

`DATABASE_PATH=<fresh unique temporary database>`, `LLM_PROVIDER=local`;
resolved path printed and asserted inside the temp directory; development
database SHA-256/size/mtime verified before and after every write-capable
run and never opened; ports 8000/8501 free; temp databases/processes removed.

## 14. Rollback plan

Revert the single production file (`app/api/deps.py`) to `e4d8be8`, remove

transaction state involved.

## 15. Stop conditions

Create `docs/development/BLOCKER_REPORT_V0.9.5_H2D2.md` and stop if: the ten
Ports are not exactly the H1/G-approved set; a Port is already bound
unexpectedly; a Port has no eligible accessor or maps to multiple accessors;
an accessor requires multiple Port types; a Union/combined contract is
required; an accessor returns different object types across construction
paths; structural satisfaction fails; direct imports create a cycle;
`TYPE_CHECKING`/unresolved annotations or `cast` are required; a function
body, Router signature, `Depends(...)`, app-state attribute, composition, or
Port definition must change; OpenAPI/dependency-graph parity cannot be
preserved; contract counts change; the research-export baseline cannot be
restored; the development database changes; or completion requires H2E work.

A known lifecycle-race failure is not an implementation blocker but prevents
final verification closure.

## 16. Deferred H2E work

H2E (final contract freeze and documentation) is not started. H2D2 stops
after its final report.
