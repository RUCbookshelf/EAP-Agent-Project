# v0.9.2.1 SPEC — Pixel Art UI Verification Closure

Frozen on 2026-07-31. This version is a verification-and-closure task only.

The v0.9.2 Pixel Art UI implementation exists in commit `d524be3`. The goal
is to provide direct evidence that the redesign starts successfully, renders
correctly in English and Simplified Chinese, works on desktop and mobile, has
no console errors or horizontal overflow, preserves keyboard focus, follows
the Pixel Art style rules, preserves validated backend behavior, contains no
credentials, and is fully documented.

## Scope boundary

Permitted: Playwright installation, Chromium installation, browser-test
repair, narrowly scoped UI defects exposed by verification, Pixel Art CSS
violations, responsive overflow, localization leakage, focus states,
verification scripts, deterministic screenshots, verification documentation,
temporary browser-artifact cleanup.

Prohibited: new pages, new features, new metrics, new diagnoses, corpus work,
ML, scoring, CEFR, proficiency, new practice types, teacher management,
pilot workflows, questionnaires, consent forms, cloud deployment, LLM
fine-tuning, enabling DeepSeek by default, database migrations, backend
changes.

## Verification requirements

### Playwright environment
- Install `playwright` Python package in the project venv
- Install Chromium via `python -m playwright install chromium`
- Verify Chromium launches

### Service startup
- FastAPI health `GET /api/v1/system/health` returns HTTP 200
- `GET /docs` returns HTTP 200
- Streamlit root returns HTTP 200
- Services stopped cleanly afterward

### Page coverage
All twelve pages verified: 6 Student (Home, Writing, Feedback, Revision,
Practice, Learning Journey) + 6 Research (Overview, Evidence, CALF Measures,
Learning Process, Research Data, System Audit). Each page must load without
uncaught exception, display localized title, preserve role separation, use
Pixel Art design system, contain no raw localization key, no unintended
horizontal overflow, keep primary controls reachable.

### Viewports and locales
Four combinations, all directly executed:
1. English desktop 1280x900
2. Simplified Chinese desktop 1280x900
3. English mobile 390x844
4. Simplified Chinese mobile 390x844

### Browser console and page errors
Listeners for console errors, uncaught page exceptions, failed critical
network requests. Zero unexpected console errors; zero unexpected page
exceptions. No raw localization keys; no duplicate widget key errors; no
Streamlit rendering exceptions. Known harmless framework messages may be
allow-listed only with documentation.

### Horizontal overflow
`document.documentElement.scrollWidth <= window.innerWidth` and
`document.body.scrollWidth <= window.innerWidth` on every page at desktop and
mobile. Account for hard shadows, focus outlines, evidence quotes, tables,
text areas, long labels, sidebar. Controlled table-container scrolling is
acceptable only when documented.

### Pixel Art style audit
Fail on: non-zero border-radius, gradients, gradient text, blur, backdrop
blur, glassmorphism, soft shadows, shadows with blur radius, transition
duration > 0, transition-all, CSS animations, opacity fades, Inter, Roboto,
Geist, thin borders on primary components, decorative single-side borders,
detectable nested cards. Document unavoidable framework-controlled
exceptions.

### Computed-style browser audit
Inspect computed styles for representative app-owned components: primary
button, secondary button, text input, text area, select wrapper, card,
notice, status label, timeline event, metric card, sidebar navigation item.
Check border-radius zero, no gradient background image, no blur/backdrop
filter, no soft box shadow, transition duration zero, animation none,
border thickness consistent, focus visible.

### Interaction states
Buttons: default/hover/active/keyboard-focus/disabled. Inputs:
default/focused/filled/validation-error/disabled. Navigation:
default/selected/keyboard-focus/wrapped-mobile-label. Expandables:
collapsed/expanded. Status labels: success/warning/error/unavailable/
candidate/insufficient-evidence. Immediate state changes; visible keyboard
focus; no clipped focus.

### Role separation
Student View must not expose analyzer versions, internal metric IDs,
Evidence IDs, Diagnostic Gate internals, configuration versions, provider
details, database IDs, internal confidence, Research Data export controls,
System Audit details. Add direct assertions.

### Localization
Identical en/zh_CN key sets; no raw keys; no English leakage in Chinese
mode; Chinese labels wrap; language switching does not trigger analysis,
exercise creation, or DeepSeek; essays/evidence/feedback not translated.

### Practice rerun safety
Browser navigation, language switching, reruns, refreshes must not create
duplicate Exercise Instances, overwrite attempts, mark empty responses
complete, or invoke DeepSeek unexpectedly.

### Screenshots

credentials, API keys, private paths, provider secrets. No browser caches
committed.
