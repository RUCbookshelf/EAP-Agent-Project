# v0.7 SPEC — Task-aware Learner Model 2.0

Status: `completed`. Authorized scope ends after v0.7; v0.8 and CALF remain `not_started`.

## Outcome

Upgrade the existing `LearnerProfileService` / `ProgressService` / `learner_profile_snapshots` path in place:

`submissions -> representative draft selection -> task clusters -> version/data checks -> metric and diagnostic trajectories -> current learning targets -> traceable history evidence -> immutable Learner Profile Snapshot v2 -> screened FeedbackContext`.

No parallel profile, dashboard, snapshot, metric-history, or issue-history subsystem is introduced.

## Frozen engineering decisions

- Application `0.7.0`; database migration `8`; profile `learner-profile-v0.7.0`.
- Task Cluster `task-cluster-v0.7.0`; metric trajectory `metric-trajectory-v0.7.0`; diagnostic trajectory `diagnostic-trajectory-v0.7.0`; data sufficiency `data-sufficiency-v0.7.0`; learning target `learning-target-v0.7.0`; history registry `history-evidence-v0.7.0`.
- Prompt/Schema `feedback-prompt-v0.7.0` / `structured-feedback-v0.7.0`; v0.6.1 diagnostic safeguards remain unchanged.
- Migration 8 extends the existing append-only Snapshot table and adds an append-only history-evidence registry. It does not replace the Snapshot table or modify old JSON.
- New Snapshot IDs use `LPSnnnnnn`; historical `LPnnnnnn` IDs remain valid and queryable.
- Migration 8 preserves `config-v0.6.2` and activates its validated child `config-v0.7.0`. Rollback reactivates the parent.
- Task clusters are deterministic local rules. No LLM clustering, embeddings, model training, CEFR, overall score, CALF total, grammar-error measure, or paid service is added.
- The default representative policy is `final_or_latest`; supported alternatives are `first_draft_only`, `latest_draft_only`, and `all_drafts_research_mode`.
- Default task-cluster separation uses genre, inferred writing purpose, timed status/time band, normalized tool-use class, independent/revision status, conservative prompt family, Analyzer family, Metric-version signature, text validity, input quality, and required metadata.
- Metric directions are descriptive signals. Two points produce only a pairwise status; at least three compatible points are required for a direction.
- Only `selected_priority` is primary diagnostic-trajectory evidence. Eligible is auxiliary; monitored/suppressed/insufficient remain researcher audit only.
- Historical evidence may raise the relevance of a current selected priority but may never create a current diagnosis, bypass the gate, or restore suppressed/monitored signals.
- Zero current learning targets is valid. Maximum current learning targets is two.
- Strength patterns use verified textual strengths only; length/MATTR/connective/parser counts cannot create strengths.

## Data contracts

`LearnerProfileSnapshot` remains the compatibility model and gains v2 fields: `profile_version`, `generated_at`, source/representative/excluded IDs, task clusters, metric trajectories, diagnostic trajectories, current learning targets, strength patterns, data sufficiency, comparability summary, analysis/algorithm versions, history evidence, representative strategy, configuration version, and limitations. Old v0.3 fields remain readable.

Every v2 History Evidence row stores the student, evidence type, source submission/AnalysisRun/diagnosis/metric/Snapshot/Task Cluster IDs, evidence text, optional offsets, evidence status, version compatibility, confidence, and limitations. Provider-visible IDs must exist in the registry.

## Conservative configured defaults

- Pairwise minimum tasks: 2.
- Provisional pattern minimum tasks: 3.
- Adequate descriptive trend minimum tasks: 5.
- Emerging: 2 comparable tasks and at least 1 selected priority.
- Recurring: 3 comparable tasks and at least 2 selected priorities.
- Persistent: 3 comparable tasks, at least 2 selected priorities, reliable evidence in every task, and a current verified selected priority.
- Recently reduced: at least 2 prior selected occurrences and no selected priority in the latest 2 compatible tasks.
- Metric direction minimum: 3 points; incompatible Analyzer/Metric versions and Task Clusters are separated.
- Feedback context limits: 3 metric trajectories, 3 diagnostic trajectories, 5 history evidence items.

All values are unvalidated prototype parameters requiring literature and human-coded calibration.
