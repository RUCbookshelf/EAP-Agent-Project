# v0.8 SPEC — CALF Measurement Foundation

Status: `completed` on 2026-07-30. This release establishes auditable CALF measurement infrastructure. It does not complete all CALF measures and does not create a CALF total, writing score, proficiency/ability/CEFR judgment, automatic grammar-accuracy system, validated T-unit/clause measure, teacher annotation platform, model training, paid-service dependency, cloud deployment, WeChat client, or v0.9 feedback–exercise–transfer loop.

Authorization: the project owner explicitly authorized v0.8 on 2026-07-30. The authorization supersedes earlier roadmap/version stop markers only for the bounded work below. Existing architecture, evidence, validation, append-only history, secret, verification, documentation, and independent-commit gates remain binding.

## Outcome and interpretation boundary

The release must provide a traceable chain:

`Construct → Subconstruct → Analysis Unit → Measurement Specification → Automation Level → Calculation → Metric Confidence → Version Compatibility → Longitudinal Research → Audit`

CALF is represented as separate constructs and measures. An observed value is not automatically an interpretation. Higher complexity, lexical diversity, accuracy, or output rate must not be translated into better writing, ability, mastery, learning, proficiency, CEFR, a score, a revision priority, or a targeted exercise.

## Registries and contracts

### Construct Registry

Register `syntactic_complexity`, `lexical_complexity`, `accuracy`, and `product_fluency` at construct version `0.8.0`. Each definition records display name, definition, subconstructs, status, interpretation boundary, references, and limitations. Supported construct states are `prototype`, `research_ready`, `validation_pending`, `unavailable`, and `deprecated`; v0.8 constructs are never described as educationally validated. Coherence, rhetorical organization, and revision process remain future non-core extension seams.

### Measurement Specification

Every registered measure records metric/version, construct/subconstruct, analysis unit, formula, parameters, numerator/denominator where applicable, normalization, minimum input requirements, automation level, measurement status, output unit/range, direction boundary, student-feedback/diagnosis/revision-priority/longitudinal eligibility, reference IDs, limitations, and version compatibility.

Measurement statuses: `research_metric`, `descriptive_proxy`, `automatic_candidate`, `manual_annotation_required`, `unavailable`, `deprecated`.

Automation levels: `deterministic`, `rule_based`, `parser_dependent`, `external_resource_dependent`, `manual`, `hybrid`.

Metric lifecycle: `draft`, `prototype`, `active_research`, `validation_pending`, `deprecated`, `retired`. Registration rejects duplicate ID/version and activation requires formula, parameters, analysis unit, minimum requirements, limitations, fixture evidence, and a reference/specification basis.

### Analysis Unit Registry

Support `raw_character`, `normalized_word_token`, `lemma`, `sentence`, `paragraph`, `dependency_node`, `noun_chunk_candidate`, `clause_candidate`, `t_unit_candidate`, `validated_clause`, `validated_t_unit`, `error_span_candidate`, `validated_error_span`, and `timed_writing_event`. Units record version, generation method, Analyzer, offsets, parent/children, confidence, validation status, human-review fields, and limitations.

Validation states: `automatic_candidate`, `validated_automatic`, `human_confirmed`, `rejected`, `not_available`. Candidate clause/T-unit units must never be silently promoted to validated units.

## Scoped measures

### Lexical diversity and density

- Bring TTR and MATTR into the CALF specification without silently changing historical versions.
- Implement deterministic, independently testable MTLD with configurable threshold (default 0.72), forward/reverse/combined values, partial-factor method, token count, normalization, and intermediate values.
- Implement deterministic, independently testable HD-D with configurable sample size (default 42), type frequencies, hypergeometric method, explicit short-text policy, token count, normalization, and intermediate values.
- Compare MTLD and HD-D against a trustworthy published/reference implementation or fixed public reference values. Record licenses/versions/differences for any dependency; self-implemented algorithms require unit, boundary, reversed-text, short-text, and reference tests.
- Specify lexical density as content POS `NOUN`, `PROPN`, `VERB`, `ADJ`, `ADV` over alphabetic spaCy tokens; punctuation/numbers are excluded, finite/content AUX handling is explicit, and parser/POS limitations remain visible.
- Keep lexical diversity, density, and sophistication distinct. Unless an authorized, versioned frequency resource and complete operating definition already exist, lexical sophistication is registered as `unavailable`.

### Syntactic foundation

Register dependency depth, noun-chunk length, clause-like dependencies, coordinator tokens, conjunct dependencies, coordinated-structure candidates, finite-verb candidates, and long-sentence candidates as `automatic_candidate`. They are not T-unit/clause/subordination/coordination/phrasal/overall syntactic-complexity measures.

Provide a framework-neutral `SyntacticUnitSegmenter` (or equivalent) with sentence, clause-candidate, T-unit-candidate, and validation operations. Candidate outputs include offsets, source sentence, rule IDs, parser evidence, confidence, relationships, status, and limitations. They are research-audit-only by default and cannot calculate formal MLT, C/T, or DC/T. Reserve annotator, timestamp, manual decision, corrected offsets, guideline version, and adjudication fields; no full teacher UI is required.

### Accuracy foundation

Provide an Error Annotation schema/repository interface with stable ID, submission/offset/original/correction/category, source, status, annotator, guideline version, and confidence. Sources include `human`, `imported_corpus`, `automatic_candidate`, `external_tool`, and `llm_candidate`. Only confirmed human/imported-corpus annotations are eligible inputs.

Pre-register errors per 100 words, error-free clause/T-unit ratios, and grammatical/lexical error density as `manual_annotation_required`. Without eligible annotations, return `unavailable` with the explicit reason that validated error annotations are unavailable; never return zero. spaCy anomalies, dictionaries, DeepSeek suggestions, long sentences, low-frequency words, or parse failures are never error gold standards.

### Product fluency foundation

Add/audit `writing_started_at`, `writing_submitted_at`, `active_writing_duration_seconds`, `timing_source`, and `timing_quality`. Sources: `client_timer`, `server_timestamp`, `manual_report`, `imported`, `unknown`; quality: `verified`, `estimated`, `self_reported`, `incomplete`, `unavailable`.

`time_limit_minutes` is only a ceiling and must never be used as actual duration. `writing_output_rate_wpm` is calculated only for timed writing with positive actual duration, accepted timing quality, acceptable input quality, and no unexplained interruption. Its status is `descriptive_proxy`; historical records without actual duration remain unavailable.

## Result, confidence, persistence, and versioning

Extend Metric Confidence with measurement/automation status, analysis-unit validation, Analyzer/fallback/model state, text length, parameters/resources, manual annotation state, timing quality, task comparability, metric/unit versions, and missing data. Confidence and magnitude remain separate; CALF measures default to diagnosis/revision-priority/targeted-practice ineligible.

CALF Metric Results store construct/subconstruct, measurement/automation status, analysis-unit version, parameters, numerator/denominator, intermediate values, confidence, eligibility, resources, limitations, and metric version. Reanalysis creates a new AnalysisRun and never overwrites historical MetricResults or Snapshots. Query and longitudinal logic must preserve exact/declared metric and analysis-unit compatibility.

Only compatible, sufficiently confident, task-comparable measures may enter research Metric Trajectories. Initial candidates are TTR (cautious), MATTR, MTLD, HD-D, lexical density, and reliable writing output rate. Parser/unit/error candidates and unreliable timing do not enter formal longitudinal series. Trend language reports only observed comparable values and never ability or fluency improvement.

Additive migration 10 (subject to the repository's actual next version) must initialize an empty database, upgrade migration 9 without loss, keep historical analyses/results/snapshots readable, append new structures, roll back logically, and never fill missing historical duration with zero. Create and activate child `config-v0.8.0` without overwriting `config-v0.7.1`; all CALF parameters are allowlisted, validated, versioned, documented, and rollback-capable.

## Feedback isolation, API, and UI

All v0.8 CALF measures default to `eligible_for_diagnosis = false`, `eligible_for_revision_priority = false`, `eligible_for_targeted_practice = false`, `expose_to_student_feedback = false`, and `expose_to_deepseek = false`. Existing Diagnostic Gate, exact-evidence validation, prompt manifest/hash, retry/server-repair, Pydantic, history-ID, and fallback protections remain unchanged. CALF data may enter a future prompt only through an explicit versioned rule/configuration; v0.8 keeps this off.

Add backward-compatible equivalent APIs for constructs, metrics/specifications, submission CALF results, analysis/syntactic units, student CALF trajectories, append-only CALF reanalysis, and read-only/error-annotation foundations. `unavailable` is a valid result, not an HTTP error; internal sensitive information is never returned; CALF reanalysis is local-only and does not call DeepSeek.

Add a CALF Research view grouped into Lexical Complexity, Syntactic Complexity, Accuracy, and Product Fluency, plus expanded Research Audit for registries, parameters, intermediate values, resources, compatibility, exclusions, and human-validation state. Each item shows value/status/confidence/unit/version/minimum requirements/limitations. Student view shows no CALF dashboard/total/level/color rating/progress/ranking/ability label and may show only the notice that research measures are not writing scores. Empty states must explain unavailable Accuracy, missing actual duration, and candidate-only syntax.

On completion mark v0.8 `completed`, leave v0.9 `not_started`, state that full CALF/automatic Accuracy/validated syntactic complexity are not complete, issue the final acceptance summary, and stop.

If work requires a parser candidate to be called a validated unit, an unauthorized frequency list, time-limit-derived duration, DeepSeek as error gold standard, a CALF/ability/CEFR/overall score, bypassing the Diagnostic Gate, overwriting history, migration data-loss risk, a paid service, model training, a stored/exposed API key, weaker earlier verification, an unverifiable key algorithm, persistent in-scope unfixable tests, or irreversible Git operations, create `docs/development/BLOCKER_REPORT_V0.8.md` and stop.
