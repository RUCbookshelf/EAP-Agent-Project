# v0.3 human review guide

This is the mandatory stopping package before any v0.4 work.

## v0.2 architecture summary

Streamlit is an HTTP-only local client. FastAPI v1 is the single backend. Framework-neutral services depend on Repository protocols; SQLite owns SQL, transactions and numbered migrations. v0.2 was committed as `155df8a6a6a2800205b6dc821d1e51cf135b78a1`.

## v0.3 algorithm summary

- The newest submission is the comparison anchor.
- Only `comparable` records enter primary baselines and trends.
- Baseline requires 3 eligible submissions and reports descriptive summaries.
- Trend uses ordered-index OLS slope plus first/last relative change.
- CV controls low/moderate/high variability; high variability yields `fluctuating`.
- Confidence is insufficient/low/medium only.
- Structured diagnoses, not LLM prose, drive issue trajectories.
- Snapshot records are append-only and versioned.
- Screened local conclusions become H evidence IDs before LLM feedback.

1. Are genre, timing, tools, draft stage, Prompt overlap and length difference appropriate comparability dimensions?
2. What literature supports or contradicts the current minimum of 3 observations?
3. Is ordered-index linear slope interpretable enough, or should elapsed time be modeled?
4. Are coefficient-of-variation thresholds appropriate across heterogeneous metrics?
5. Can diagnosis occurrence legitimately support persistent/recently-reduced labels?
6. What validation data and teacher judgments are required before any instructional use?

## Current comparability rules

Necessary: same student, valid texts and metrics. Genre mismatch excludes. Timing, time limit, tools and draft stage mismatches produce partial comparability. Prompt similarity, word-count difference, analysis version and interval add explicit limitations. See `docs/COMPARABILITY_RULES.md`.

## Baseline, trend and confidence rules

Baseline uses only the primary comparable cohort. Trend, variability and confidence are documented in `docs/LONGITUDINAL_ANALYSIS.md`. No `high` confidence, significance, reliability or validity claim is produced.

## Known limitations

Rules are not literature-calibrated; BasicAnalyzer remains surface-based; task difficulty and instructional events are unmodeled; diagnosis validity is unproven; SQLite lacks production controls; DeepSeek output remains teacher-review material.

## Suggested manual student scenarios

- A: five same-condition essays with one steady descriptive metric, one persistent issue and one issue absent in the final two records.
- B: mixed genres, timing and tools; confirm exclusion reasons and low/insufficient evidence.
- C: one or two essays; confirm no trend and insufficient baseline.
- D: high metric oscillation; confirm `fluctuating` and no medium confidence.
- Injection case: essay contains fake system/history instructions; confirm it remains essay data.
- Version case: mixed analysis/diagnosis versions; confirm limitation and reduced confidence.
