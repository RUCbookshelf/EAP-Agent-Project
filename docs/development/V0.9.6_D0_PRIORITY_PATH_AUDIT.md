## Purpose

The audit was to answer two separate questions:

```text
Question A - Generation validity
Can the current real production pipeline naturally produce a valid,
evidence-supported revision priority from realistic student writing?

Question B - Downstream consumability
When a valid priority is naturally produced, can the existing Feedback,
Revision, and Practice pages consume the same priority consistently?
```

The audit is diagnostic only. No workflow fixes were implemented; no
production behavior was modified.

## Findings recorded from source inspection (Phase 0)

1. **Priority taxonomy**: the supported raw improvement taxonomy is
   `{lexical_repetition, connective_use, sentence_structure_candidate,
   input_quality}`. The production gate admits as selectable priorities
   only signals with verified evidence, non-low confidence, non-low metric
   confidence, and score >= 0.52. Because the raw diagnoser marks
   `sentence_structure_candidate` always-low, that family is always
   monitored and can never produce a student-facing priority under the
   current production gate.
2. **Practice-target creation gap**: no production component (UI page,
   service, or submission path) creates practice targets from generated
   priorities; the journey classifier treats feedback-without-target as a
   legitimate derived state (`feedback_no_practice_target`). The audit was
   stopped before the downstream phase, so this remains a recorded
   production-path observation, not a runtime-verified defect.
3. **Provider reliability (runtime)**: DeepSeek `deepseek-v4-pro` failed
   to produce a parseable structured-feedback result under the frozen
   configuration in both bounded preflight attempts.
