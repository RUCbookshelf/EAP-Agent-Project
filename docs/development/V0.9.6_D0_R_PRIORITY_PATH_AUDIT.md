## Original D0 blocker and repaired provider state

The original v0.9.6-D0 audit completed Phases 0-2 (baseline, protocol
preregistration, five-case corpus freeze) and stopped at the real-provider
preflight (classification D0-E): `deepseek-v4-pro` defaulted to thinking
mode, truncated the JSON (`finish_reason=length`), and timed out the
correction attempt at 30s, so fallback dominated.

The provider repair was completed and closed through v0.9.6-DP0, DP0-V1, and
DP0-V2. The structured-feedback request path now explicitly disables
thinking (`thinking={"type":"disabled"}`), captures sanitized provider
metadata, and classifies truncation (`provider_output_truncated`) and
malformed JSON (`provider_json_invalid`). Frozen invariants: model
`deepseek-v4-pro`, prompt `feedback-prompt-v0.7.1`, config `config-v0.9.0`,
StructuredFeedback schema, Diagnostic Gate, 30s provider timeout,
1800/3600 token budgets, correction/fallback policy, and the 180s client
timeout.
