# v0.2 specification — local API-first cloud-ready architecture

## Goal

Run locally on Windows as Streamlit → HTTP → FastAPI → application services → Repository protocols → SQLite, while retaining all v0.1.1 safeguards and preserving a future frontend/PostgreSQL replacement seam.

## Preconditions

- Baseline tests, Streamlit, `run.bat`, database schema, code boundaries, and Git recovery commit are verified.
- No irreversible database operation is required.

## In scope

- Architecture audit; application service extraction; Repository protocols and SQLite implementations.
- Versioned, repeatable, non-destructive migrations for empty and existing databases.
- FastAPI v1 system, submission, student, history, profile, and progress endpoints.
- Pydantic API schemas, consistent safe errors, bounded input, and 404 behavior.
- Streamlit as API-only client; configurable local host/ports; dual-service `run.bat`.
- Isolation, API, repository, migration, UI-client, startup, regression, and no-key tests.
- Documentation, independent acceptance report, visualization, and Git commit.

## Out of scope

- Cloud servers, domains, PostgreSQL implementation, Redis, Kubernetes, authentication, WeChat development, validated longitudinal trends, CEFR, scores, rankings, or automated high-risk decisions.

## Architecture changes

Add `app/api`, `app/core`, `app/services`, `app/repositories`, and `app/infrastructure`. Keep v0.1.1 modules behind compatible services. API routes remain thin and Streamlit uses `app/ui/api_client.py` only.

## API changes

Add `/api/v1/system/health`, `/api/v1/system/version`, submission POST/GET, and student/history/profile/progress GET endpoints. v0.2 profile/progress explicitly report v0.3 availability instead of inventing trends.

## Database changes

Introduce numbered migrations and migration history. Preserve existing data, support empty and legacy databases, make upgrades idempotent, and isolate test databases.

## Dependency changes

Add FastAPI HTTP/testing dependencies only as needed. Continue Python 3.11.

## Test requirements

Cover all 32 groups in the governing goal: architectural isolation, API behavior, fallback and validation, repository persistence/rollback/isolation, migration paths/idempotence, UI client behavior, and actual FastAPI/Docs/Streamlit/`run.bat` startup including no `.env`.

## run.bat impact

Install dependencies, run migrations, start FastAPI on the configured fixed port, poll health, then start Streamlit on its configured fixed port. `--verify` must start and probe both services and exit cleanly.

## Documentation requirements

Update all named v0.2 documents and create `RUN_VERIFICATION_V0.2.md` plus a truthful architecture visualization.

## Acceptance criteria

All 20 v0.2 gate items in the governing objective must have direct evidence, including a clean independent Git commit.

## Stop condition

Do not start v0.3 until every v0.2 gate passes. Create `BLOCKER_REPORT.md` only for a listed hard blocker.
