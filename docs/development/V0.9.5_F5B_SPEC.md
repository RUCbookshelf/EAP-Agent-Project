# v0.9.5-F5B Specification — ResearchDataService Dependency Narrowing

**Date:** 2026-08-02
**Status:** ACTIVE
**Baseline:** `8abd6c2` (v0.9.5-F5A verification); F2 `7927ca7`, F3
`a24312a`/`256b172`, F4 `bb0c348`/`80be7f3`, and F5A `8d16cd5`/`8abd6c2`
are ancestors.

## Objective

Behavior-preserving Service dependency refactor. Replace the broad, untyped
persistence dependency of `ResearchDataService` with three explicit
consumer-owned structural Ports, remove repository-capability discovery
through `hasattr`, and supply the existing facade-owned Submission and
Research repository instances through the application composition root.
Router-level best-effort `save_export_job` behavior stays in the Router.

Target:

```text
ResearchDataService
    ├── submission_reader: ResearchSubmissionReadPort (SQLiteSubmissionRepository)
    ├── review_repository: ResearchReviewPort         (SQLiteResearchRepository)

    ├── _submission_repository
```

## 3. Exact three Port signatures

All Ports are `typing.Protocol` classes defined in `app/research/service.py`.
Signatures, parameter names, defaults, and return annotations match the
repository implementations at HEAD `8abd6c2` exactly (including the
annotation-free `list_all_submissions`). No inheritance from central
repository Protocols; no concrete SQLite imports; no `Database` import; no
`save_export_job`; no unused method.

`ResearchSubmissionReadPort`

```python
def list_all_submissions(self): ...
def list_student_submissions(self, student_id: str) -> list[dict[str, Any]]: ...
def get_submission_bundle(self, essay_id: int) -> dict[str, Any] | None: ...
```

Source: `app/infrastructure/sqlite/repositories/submission.py`.

`ResearchReviewPort`

```python
def save_human_review(self, review) -> dict: ...
def list_human_reviews(self, target_type: str | None = None, target_id: str | None = None) -> list[dict]: ...
def apply_pii_review(self, submission_id: int, reviews: list) -> list[dict]: ...
```

Source: `app/infrastructure/sqlite/repositories/research.py`.

`ResearchExportReadPort`

```python
def list_export_jobs(self) -> list[dict]: ...
def get_export_job(self, export_id: str) -> dict | None: ...
```

Source: `app/infrastructure/sqlite/repositories/research.py`.

## 4. Service constructor before and after

Before:

```python
def __init__(self, repository):
    self.repo = repository
```

After:

```python
def __init__(
    self,
    submission_reader: ResearchSubmissionReadPort,
    review_repository: ResearchReviewPort,
    export_reader: ResearchExportReadPort,
):
    self.submission_reader = submission_reader
    self.review_repository = review_repository
    self.export_reader = export_reader
```

No broad `repository`/`repo` parameter or field, no untyped persistence
parameter, no compatibility fallback, no dynamic repository selection, no
`Database` import, no concrete SQLite import. Public Service method
signatures are unchanged.

## 6. Eight method-to-owner mappings

```text
list_all_submissions, list_student_submissions, get_submission_bundle
    → ResearchSubmissionReadPort

save_human_review, list_human_reviews, apply_pii_review
    → ResearchReviewPort

list_export_jobs, get_export_job
    → ResearchExportReadPort
```

No ninth persistence method is called by the Service. `ResearchDataService`
does not call `save_export_job` (confirmed at baseline and enforced by
tests). Call order and call counts per method are preserved: `_collect`
lists all submissions once, then lists student submissions once per
distinct student; `scan_pii`/`apply_pii_review` perform one bundle lookup
before review operations; export generation performs one collection pass.

## 7. `hasattr` removal decision

Six repository-capability `hasattr` branches exist and are removed:
`list_all_submissions` (in `_collect`), `save_human_review`,
`list_human_reviews`, `apply_pii_review`, `list_export_jobs`,
`get_export_job`. The approved baseline production `Database` facade always
supplies all five Research methods and all three Submission reads, so the
capability-absent branches are unused in active production construction.
After F5B the Service calls all eight methods directly through their Ports;
no hidden capability-absent fallback is preserved.

## 8. Human Review and PII transaction rules

`save_human_review`, `list_human_reviews`, and `apply_pii_review` remain
complete repository-owned single-method operations with their existing
validation, lookup, commit, rollback, and error behavior. The Service never
splits a repository-owned write into Service-level checks plus writes. No
shared transaction is introduced between Submission reads, Human Review
writes, PII Review writes, Export Job reads, or export-file generation;
per-method transaction boundaries are unchanged.

## 9. Export Job read rule

`list_export_jobs` and `get_export_job` route through `ResearchExportReadPort`
with ordering, filters, limits, missing-job behavior, returned shapes,
status interpretation, timestamps, and identifiers unchanged.
`save_export_job` is absent from all three Ports and from
`ResearchDataService`.

## 10. Router-owned `save_export_job` rule

The responsibility boundary is unchanged:

```text
ResearchDataService.run_export(...)
    → generates and returns the export result

Research router (POST /api/v1/research/export/run)
    → attempts repository.save_export_job(...) after export generation
      with the existing best-effort try/except-pass behavior
```

The Router keeps its current direct repository dependency
(`Depends(get_repository)`) for that write. Export generation and Export Job
persistence are not atomic; an audit-row write failure never retroactively
fails the completed export. The Router is not edited in F5B.

## 11. Export-file safety plan

`run_export` writes `research_exports/export_<ts>/{records.jsonl,
records.csv, manifest.json}` (module constant `_EXPORT_BASE`, not
configurable, unchanged). Every write-capable run snapshots the
`research_exports/` directory listing before and after; newly created
directories are test artifacts and are removed after the run; pre-existing
user exports are never opened, modified, or deleted. Export contents,
ordering, file names, and formats are unchanged. The development database is
never opened.

## 13. Focused test plan

Ports: exact method sets; `inspect.signature` parity with
`SQLiteSubmissionRepository` and `SQLiteResearchRepository`; structural
satisfaction by the repositories and by `Database` (legacy verification
only); both Research Ports satisfiable by the same repository instance.

Service: a minimal three-method Submission reader, three-method Review
Port, and two-method Export reader are sufficient; no unrelated repository
method requested; no dynamic capability discovery; all-submission and
student-scoped paths retain call order; missing Bundles retain current
handling; Human Review and PII success each perform exactly one approved
repository write; validation/lookup failure performs zero corresponding
writes; repository exceptions propagate unchanged; Export Job listing and
retrieval retain output and ordering; `ResearchDataService` never calls
`save_export_job`; no shared transaction; export preview/export-file output
matches baseline expectations.

Composition: both app-construction paths wire `repository._submission_repository`
and the same `repository._research_repository` instance to both Research
Ports (identity assertions); same `_connection_manager`; no second Database,
connection manager, or repository graph; F2-F5A composition unchanged.

Router boundary: `run_export` itself performs no Export Job write; the
Router still attempts `save_export_job` after a successful export through
the same repository dependency; audit-row success preserves the response;
audit-row failure preserves best-effort behavior; no endpoint contract
changes.

## 14. Rollback plan

All changes are reversible through the two focused commits
(`refactor(v0.9.5-f5b): ...`, then `test(v0.9.5-f5b): ...`); `git revert`
of either commit restores previous behavior. No schema, SQL, data
migration, or export content is touched, so no database or file rollback is
required.

## 15. Stop conditions

Stop and create `docs/development/BLOCKER_REPORT_V0.9.5_F5B.md` if completion
requires changing a repository implementation, changing SQL, changing a
transaction boundary, introducing a shared transaction, adding a facade
public method, changing the `Database` constructor, adding `save_export_job`
to ResearchDataService, moving Router persistence into the Service, changing
Router best-effort failure semantics, changing export serialization or
privacy rules, modifying another Service dependency, changing API paths or
schemas, adding a compatibility fallback inside `ResearchDataService`,
adding a proxy/Service Locator/DI framework, opening or writing the
development database, modifying existing user exports, or beginning
write-orchestration narrowing or a later stage. Also stop if the Service
calls an unrecorded ninth persistence method, an active production
constructor lacks the required methods, an active caller cannot be updated
with the existing facade-owned repositories, or behavior preservation
requires a cross-repository shared transaction.
