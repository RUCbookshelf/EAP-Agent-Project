# v0.9.2 SPEC — Pixel Art UI Redesign

Frozen on 2026-07-31. This version transforms the existing v0.9.1 Streamlit
interface into a coherent, accessible, responsive Pixel Art design system while
preserving all validated application behavior.

This is a major UI redesign, not a backend feature version.

## Authorization boundary

Pixel Art visual identity, centralized CSS token system, reusable component
redesign, global application shell, all 12 page renderers (6 Student + 6
Research), form control restyling, accessibility audit, responsive verification,
i18n updates, test suite expansion, Playwright verification, documentation, and
one focused Git commit.

No new backend logic, CALF calculations, diagnostic rules, linguistic metrics,
practice-domain behavior, scoring, proficiency claims, or machine learning.

## Conflict-resolution rule

The specification contains conflicting instructions. Priority:

1. Absolute prohibitions in this spec;
2. Pixel Art visual principles;
3. Attached color tokens;
4. Attached spacing and typography scales;
5. Existing Streamlit technical constraints.

## Absolute prohibitions

- No rounded corners;
- No gradients;
- No soft shadows;
- No blur;
- No glassmorphism;
- No opacity animation;
- No smooth animation;
- No CSS transition except `transition: none`;
- No nested cards;
- No decorative single-side accent borders;
- No thin borders on primary pixel-art components;
- No Inter, Roboto, Geist, or externally distributed font files;
- No game-like elements (scores, XP, levels, mastery badges, achievements,
  rankings, CEFR judgments, proficiency judgments, game rewards).

## Canonical color system

Limited solid-color palette:

- Primary dark: `#1a1c2c`
- Background white: `#ffffff`
- Secondary surface: `#f4f4f4`
- Action red: `#ff004d`
- Success green: `#00e436`
- Information blue: `#29adff`
- Attention yellow: `#ffec27`

At most two additional neutral colors for text, disabled states, or table
separation.

No gradients. No semi-transparent decorative surfaces. No gray text on colored
backgrounds without WCAG AA verification. Never rely on color alone to
communicate status.

## Pixel Art design tokens

Centralized CSS custom properties in a single application-owned file.

### Borders
- Desktop primary: `4px solid #1a1c2c`
- Small mobile: `2px solid #1a1c2c`
- Primary components must not use 1px borders.

### Hard shadows
- Small: `2px 2px 0 #1a1c2c`
- Medium: `4px 4px 0 #1a1c2c`
- Large: `8px 8px 0 #1a1c2c`
- No blur radius, no spread-based soft elevation, no transparent drop shadows.

### Radius
- Canonical: `0`

### Transition
- Canonical: `none`

### Button behavior
- Default: 4px border, 4px hard shadow
- Hover: reduced hard shadow, optional immediate 2px positional offset
- Active: no hard shadow, immediate positional offset
- Focus: visible blue or yellow hard outline
- Disabled: distinct state, not opacity alone

### Card behavior
- White or approved solid background, square corners, thick dark border, hard
  offset shadow
- No nested cards
- Interactive cards: immediate hard shadow/position change on hover
- Static cards: no decorative hover movement

## Typography

- Monospace/pixel-compatible stack: `ui-monospace, Cascadia Mono, Cascadia Code,
  Consolas, SFMono-Regular, Menlo, Monaco, Liberation Mono, Courier New,
  monospace`
- No downloaded/bundled/generated/distributed font files
- Major headings: heavy weight; section headings: bold; body: readable monospace
- Chinese text must remain readable
- Body line height readable; line length 65-75 characters; research tables not
  unreadably small

## Global page structure

Single coherent application shell with:
- Application identity
- Role selector (Student/Research)
- Language selector (en/zh_CN)
- Compact navigation (6 pages per role)
- Current page title and optional description
- Main content area
- System/privacy notices

Square corners, solid colors, strong structural borders, usable at 390x844.

## Component catalog

All app-owned components follow the Pixel Art system. Reusable components in
`app/ui/components.py`: page header, navigation item, section heading, primary
button, secondary button, destructive button, disabled button, text input
wrapper, text area wrapper, select wrapper, checkbox/radio treatment, tab
treatment, card, metric card, feedback priority card, evidence quotation,
limitation notice, warning notice, success notice, error notice, empty state,
status label, timeline event, audit record, filter area, table container,
pagination controls, expander, dialog/modal, progress/workflow indicator.

## Form control requirements

Restyle Streamlit form controls with white or approved solid background, square
corners, thick dark border, dark readable text, clear placeholder text, visible
blue focus inset or outline, and immediate state changes. No soft focus glow or
rounded dropdown surfaces. Do not damage native accessibility or keyboard
behavior. Document Streamlit-controlled elements that cannot be fully restyled.

## Page specifications

### Student View
1. **Home**: Clear learning workflow with primary action immediately visible.
   No nested cards, no technical state.
2. **Writing**: Large readable writing area, clear prompt, logical metadata
   grouping, visible required-field states, strong submit action.
3. **Feedback**: Strengths, max 2 revision priorities with evidence quotes and
   actionable suggestions. No raw metrics as primary feedback.
4. **Revision**: Source draft, earlier feedback, revised text, compare,
   observations. Visual distinction for change types without color alone.
5. **Practice**: Target, reason, evidence, instructions, constraints, response,
   attempt history, conservative evaluation. No grades or mastery.
6. **Learning Journey**: Chronological pixel-art timeline with square markers
   and text labels. Not levels/quests/achievements.

### Research View
1. **Overview**: Compact research console with grouped information regions.
2. **Evidence**: Filters, audit fields, submission/analysis/diagnosis details,
   readable long spans, controlled table overflow.
3. **CALF Measures**: Grouped metric cards by construct with status, confidence,
   limitations. No simplistic good/bad labels.
4. **Learning Process**: Complete evidence chain with square timeline nodes.
   System vs. human-reviewed distinction.
5. **Research Data**: 8 subsections with consistent Pixel Art controls.
6. **System Audit**: Restrained terminal-like layout. No credentials or secrets.

## Accessibility

- WCAG 2.1 AA text contrast
- Visible keyboard focus, descriptive labels, semantic headings
- No status by color alone
- Readable Chinese typography, accessible form controls
- No flashing, rapid animation, or unnecessary motion
- Usable at browser zoom, clear disabled states, adequate target sizes
- `prefers-reduced-motion` disables any remaining browser-controlled movement

## Responsive design

Verified at: desktop 1280x900, tablet, mobile 390x844.
No horizontal overflow, understandable navigation, cards flatten to stacked
regions, reachable buttons, usable inputs, Chinese labels wrap correctly,
tables use controlled scrolling, hard-shadow offsets included in overflow.

## Internationalization

Update `locales/en.json` and `locales/zh_CN.json`. Identical key sets, no raw
keys displayed, no accidental English leakage in Chinese mode, safe English
fallback, visual labels fit in both languages, language switching must not
trigger reanalysis or provider calls.
