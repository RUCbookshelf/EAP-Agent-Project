# v0.9 Human Review Guide

## Purpose

This guide helps researchers verify the v0.9 Feedback-Practice-Transfer Foundation implementation.

## Verification Steps

### 1. Practice Target Creation
- Submit an essay with a diagnostic output
- Verify a Practice Target is created only for selected (non-suppressed) diagnoses
- Verify suppressed diagnoses do not create Practice Targets
- Check the target includes source submission, diagnosis, and evidence IDs

### 2. Exercise Generation
- Navigate to the Practice page in Streamlit
- Load practice targets for a student
- Generate an exercise: verify deterministic template output
- Verify unsupported target codes return "practice not available"
- Verify no DeepSeek call occurs (generation_provider = deterministic_template)
- Reload the page: verify no duplicate exercise instances

### 3. Exercise Attempts
- Submit a valid exercise response
- Verify the attempt is stored with attempt_number and status
- Submit a second response; verify it appends (does not overwrite)
- Submit an empty response; verify it is stored as INVALID_INPUT

### 4. Practice Evaluation
- Verify evaluation uses rule_based method
- Check completion_status and target_action_status are populated
- Verify no "mastered", "proficient", or causal language in evaluation output
- Check limitations field references task-specific evidence

### 5. Learning Journey
- Navigate to Learning Journey page
- Enter a student ID with practice history
- Verify chronological event timeline displays
- Check that each event has appropriate boundary language

### 6. Practice Audit
- Navigate to Practice Audit page (Research View)
- Load audit records for a student
- Verify all practice tables are accessible in the audit view
- Check that student-facing views do not expose raw audit data

### 7. Locale Verification
- Switch between English and Chinese in the sidebar
- Verify all Practice, Learning Journey, and Practice Audit text translates
- Check for no raw locale keys (tab_practice, tab_practice_audit, etc.) in UI
- Verify locale switching does not trigger duplicate exercise creation

### 8. Playwright Verification
- Run test_v09_playwright.py standalone
- Verify desktop (1280x900) passes
- Verify mobile (390x844) passes
- Check console for zero errors

### 9. Live A-G Validation
- Run the live validation test suite
- Verify all 20 tests pass
- Cases A-D verify practice flow without persistence
- Case E verifies DeepSeek disabled default
- Case F verifies locale parity
- Case G verifies Streamlit code structure

### 10. Database Migration
- Verify migration 12 creates 8 practice tables
- Verify config-v0.9.0 is the active configuration
- Verify rollback from 12 to 11 is supported
- Verify existing data is preserved through migration

## Pre-v1.0 Checklist
- [ ] All Practice Target flows work end-to-end
- [ ] Exercise generation is deterministic and documented
- [ ] Attempts are append-only
- [ ] Evaluations use no mastery/scoring language
- [ ] Learning Journey displays chronological events
- [ ] Practice Audit shows full audit trail
- [ ] English and Chinese locales are complete and identical
- [ ] Playwright passes at desktop and mobile
- [ ] No console errors in any view
- [ ] Git worktree is clean
