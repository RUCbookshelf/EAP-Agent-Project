# v0.9.5-F2 Specification - Low-Risk Service Repository Dependency Narrowing

**Status:** approved behavior-preserving dependency-boundary refactor
**Baseline:** `172dbe1` (v0.9.5-F1 audit commit); `7868b68` (v0.9.5-E verification) is an ancestor
**Frozen runtime:** Migration 12; 33 tables; `config-v0.9.0`; 77 API path+method pairs; 52 frontend client methods; core baseline 469 passed + 8 skipped; locale parity 520/520; `Database` facade surface 86 public methods
**Planning source:** `docs/development/SERVICE_REPOSITORY_DEPENDENCY_AUDIT_V0.9.5_F1.md` (F2-relevant sections only)

## 1. Included Services

- `ConfigurationService` - runtime dependency changes from the 86-method `Database` facade to the existing composed `SQLiteConfigurationRepository` instance.
- `LearnerHistoryService` - declared contract changes from the broad central `LearnerHistoryRepository` to a consumer-owned one-method `PriorRecordsPort`.

## 2. Excluded Services

`DashboardService`, `ProgressService`, `LearnerProfileService`, `ReanalysisService`, `CalfService`, `ResearchDataService`, `JourneyService`, `SubmissionService`, `RevisionService`, `AdminReanalysisService`, `PracticeService`, and `FeedbackPipeline` are untouched. In particular, `DashboardService` is not narrowed because its `ProgressService.create_snapshot()` path conditionally uses `get_active_configuration` through an existing `hasattr` branch; Dashboard/Progress/LearnerProfile redesign is deferred to v0.9.5-F3.

## 3. Pre-change and target dependency diagrams

Pre-change:

```text
app/api/main.py
    Database facade (runtime)
        └── ConfigurationService(repository=facade)        # broad 86-method object

SubmissionService
    └── LearnerHistoryService(database=facade)
            type contract: LearnerHistoryRepository         # 3 methods
```

Target:

```text
app/api/main.py
    Database facade
        └── existing SQLiteConfigurationRepository instance (facade._configuration_repository)
                └── ConfigurationService(configuration_repository)   # 7-method object

SubmissionService
    └── LearnerHistoryService(database=repository)          # runtime object unchanged
            type contract: PriorRecordsPort                 # 1 method
```

## 4. Exact Configuration contract

The consumer contract retained on `ConfigurationService` (`app/services/configuration.py:14-22`) contains exactly these seven methods and nothing else:

```text
list_configurations
get_configuration
get_active_configuration
create_configuration
set_configuration_validation
activate_configuration
list_configuration_audit
```

No `ping`, `migration_version`, or system methods are added. The stale central Protocol also named `ConfigurationRepository` (`app/repositories/protocols.py:74-77`) is not consolidated; name consolidation is deferred.

## 5. Exact PriorRecords contract

New consumer-owned Protocol in `app/learner/history.py`:

```python
@runtime_checkable
class PriorRecordsPort(Protocol):
    def prior_records(self, submission: EssaySubmission) -> list[dict[str, Any]]: ...
```

The signature preserves the source signature at HEAD exactly (`SQLiteSubmissionRepository.prior_records(self, submission: EssaySubmission)`, `app/infrastructure/sqlite/repositories/submission.py:108`; consumed at `app/learner/history.py:31` as `self.database.prior_records(submission)`). It does not include `save_history`, `list_student_history`, learner-profile, or analysis methods.

## 6. Runtime-object decisions

- `ConfigurationService`: both application-construction paths (`app/api/main.py:152` `_run_startup`, `app/api/main.py:317` `_build_full_app`) receive `repository._configuration_repository`, the existing `SQLiteConfigurationRepository` instance composed by the `Database` facade at `app/database/repository.py:138`. This is the existing explicit facade repository attribute already exercised by `tests/test_v095e_repository_modularization.py`; no new facade method, no constructor change, no second connection manager, no proxy/adapter, and no DI framework is introduced.
- `LearnerHistoryService`: the runtime object stays the same compatible repository/facade object passed by `SubmissionService.__init__` (`app/services/submission.py:55`). Only the declared type changes to `PriorRecordsPort`. `SubmissionService` constructor and workflow are unchanged; actual injection of an extracted Submission repository is deferred to the cross-owner stage.

## 7. Allowed files

Production: `app/api/main.py`; `app/learner/history.py`; `app/learner/__init__.py` (minimal export). `app/services/configuration.py` and `app/services/submission.py` are changed only if a minimal import/annotation adjustment is required (expected: no change). Tests: one new focused F2 contract test file (`tests/test_v095f2_service_narrowing.py`); no existing test is modified unless an import path must change (expected: none). Documentation: `docs/development/V0.9.5_F2_SPEC.md`, `RUN_VERIFICATION_V0.9.5_F2.md`, and minimal relevant updates to `CHANGELOG.md`, `PROJECT_STATE.md`, `docs/development/MASTER_ROADMAP.md`, `docs/development/CURRENT_TASK_STATE.md`, `docs/development/DECISION_LOG.md`. Verification artifacts: a small directory `verification/v0.9.5-f2/` containing the isolated database runner.

Not changed: repository implementations, `SQLiteConnectionManager`, `Database` public surface/constructor, central Protocols, migrations/DDL, FastAPI routers, UI, frontend Ports, API client, configuration schemas, domain logic.

## 8. Behavior-preservation rules

Preserve all public Service class names and methods; constructor positional compatibility; method parameters and defaults; API paths/methods/schemas; returned dicts/models; exception behavior; configuration activation/validation/rollback behavior; learner-history record selection, ordering of prior records, and return shape; repository SQL and table access; transaction boundaries and per-method commits/rollbacks; Migration 12; all 33 tables; indexes/foreign keys/constraints; active-configuration behavior; request IDs; error taxonomy; UI behavior. `LearnerHistoryService.prior_records` call arguments, filtering, sorting, and history-selection semantics are not altered.

## 9. Database-safety rules

Before every process capable of constructing `Database`: set `PYTHON_DOTENV_DISABLED=1`; remove `DATABASE_URL` from the process environment; set `DATABASE_PATH` to a new path inside a unique temporary directory; force `LLM_PROVIDER=local`; resolve settings and assert the effective database path is inside the temporary directory and is not `data/writing_feedback.db`, the v0.9.5-B backup, or any user-owned database; assert the expected fresh state; run the test/verification; close connections/processes; remove the temporary directory; verify ports are free. Before and after all write-capable verification, compare the development database file SHA-256 and modification time without opening it; stop and create a blocker report if it changes.

## 10. Tests

One new file `tests/test_v095f2_service_narrowing.py` proving: `PriorRecordsPort` declares exactly one method with the source signature; `LearnerHistoryService` constructs and runs with a stub implementing only `prior_records` (no `save_history`/`list_student_history`); the `Database` facade and `SQLiteSubmissionRepository` satisfy `PriorRecordsPort` structurally; `prior_records` delegation returns identical data; both application-construction paths supply `repository._configuration_repository` to `ConfigurationService` (not the facade); the seven Configuration methods remain callable and create/validate/activate/list/audit/active behavior is unchanged; activation remains one repository-method transaction; `DashboardService` and `LearnerProfileService` still receive the facade. Focused run: the new file plus existing Configuration, learner-history, repository, app-construction, and `test_v095e_repository_modularization.py` coverage, against a fresh isolated database. The v0.9.5-E facade-parity test remains unchanged and must pass.

## 11. Rollback plan

The implementation is one isolated commit (`refactor(v0.9.5-f2): narrow low-risk service repositories`). Rollback is `git revert` of that commit on a clean task-owned diff, followed by the focused Configuration/learner-history/repository suite and the unchanged v0.9.5-E parity contract. No schema, SQL, transaction, public-facade, Service-constructor, or UI change is part of this stage; if parity requires any such change, stop and create `docs/development/BLOCKER_REPORT_V0.9.5_F2.md` instead.
