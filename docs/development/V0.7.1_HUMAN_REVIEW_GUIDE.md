# v0.7.1 human review guide

Use only pseudonymous synthetic data. This prototype does not measure ability or replace teacher judgment.

1. **New independent task:** on Essay submission choose “Start a new independent task,” keep first/independent stage, enter metadata and submit.
2. **Revision:** choose “Submit a revision within an existing task,” then explicitly select the earlier draft. Submission must be blocked if no earlier draft is selected.
3. **Revision Group:** confirm the saved summary and Revision tab show the same Group ID; matching prompts alone must not create a group.
4. **Draft Chain:** submit linked revised/final drafts and confirm chronological sequence, stage, ID and time.
5. **First to current:** compare first/latest IDs with the Draft Chain endpoints and inspect the same deterministic comparison fields.
6. **Cross-task vs within-task:** confirm multiple linked drafts show one independent task/one representative; their changes appear only in Revision, while Progress explains cross-task insufficiency.
7. **No-history DeepSeek:** submit a new synthetic student in DeepSeek mode; expect `unavailable`, no evidence IDs, fallback false and validation passed or passed-with-server-repair.
8. **Provider classification:** use Research audit view to distinguish external success, server repair, request failure, parse failure, validation failure, correction failure and fallback.
9. **Server repair:** use the fixed scripted regression or inspect a live repaired result. Only listed fields may change; fallback remains false.
10. **Empty priority/practice:** use a draft with no selected calibrated priority. Confirm explanatory copy appears and does not claim the draft needs no revision.
11. **Major rewrite:** link an unrelated replacement draft. Confirm major-rewrite warning, `insufficient` attribution and non-assessable uptake.
12. **Positive finding:** confirm the explanation names an observable quoted feature and does not claim strong control, proficiency, mastery or writer ability.
13. **Connectives:** inspect Evidence. Confirm identical forms are deduplicated and grouped as discourse connectives versus coordinating conjunctions; no cohesion inference follows from zero detections.
14. **Student view:** confirm raw signals, gates, full provider diagnostics, complete structured connective classes and versions are hidden.
15. **Research audit view:** confirm those audit records appear, and switching view does not create feedback or Snapshot rows.
16. **Configuration rollback:** in an isolated database, roll migration 9 logically to 8; confirm `config-v0.7.0` active and historical rows readable; re-upgrade and confirm `config-v0.7.1`.
17. **Cases 1–10:** run `pytest -q tests/test_v071_reliability_ui.py`; map tests to no history, weak wording, four drafts, three tasks, zero priorities, major rewrite, request failure, validation failure, ability inference and connective grouping.
18. **Live A–C:** set `RUN_LIVE_LLM_TESTS=1`, run `pytest -q -s tests/test_live_deepseek_v071.py`, and retain only the sanitized provider/status summary described in `RUN_VERIFICATION_V0.7.1.md`.
19. **Before v0.8:** obtain explicit authorization and confirm human/educational-measurement review of thresholds, task comparability, evidence relevance, risky-language coverage, revision attribution and UI comprehension. Do not infer that v0.7.1 authorizes CALF, CEFR, scoring, model training, cloud deployment or a new frontend.

Final acceptance also requires the complete normal suite, FastAPI `/health`, `/docs`, Streamlit HTTP 200, `run.bat --verify`, key/security scan, matching docs, one independent commit and a clean worktree.
